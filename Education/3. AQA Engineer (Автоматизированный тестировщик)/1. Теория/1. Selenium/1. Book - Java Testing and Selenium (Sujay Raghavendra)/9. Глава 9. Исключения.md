# Типы исключений
В этом разделе рассматриваются различные исключения, возникающие во время выполнения автоматизированных тестов. Исключения разделены на категории для упрощения понимания причин их возникновения.

---
## Распространенные исключения в Selenium

Во время различных сценариев тестирования возникает множество исключений. Перечислить все сложно, но давайте рассмотрим наиболее распространенные случаи.

---
### Исключения соединения (Connection Exception)

Когда происходит неожиданная потеря или нарушение связи с WebDriver или браузером, возникает следующее исключение.

**`ConnectionClosedException`** — возникает при попытке взаимодействия с WebDriver, который уже закрыт.

```java
WebDriver driver = new ChromeDriver();
driver.close();
driver.getTitle(); // Это вызовет ConnectionClosedException
```

---
### Исключения взаимодействия с элементами (Element Interaction Exceptions)

Эти исключения возникают при попытке доступа или взаимодействия с веб-элементами на странице.

**`ElementClickInterceptedException`** — возникает, когда целевой элемент **скрыт** или **недоступен в момент клика.**

```java
WebDriver driver = new ChromeDriver();
driver.get("http://example.com");
driver.findElement(By.id("overlayedButton")).click(); 
// Это вызовет ElementClickInterceptedException
```

**`ElementNotInteractableException`** — возникает, когда веб-элемент **не доступен для взаимодействия**, но предпринимается попытка взаимодействия.

```java
driver.findElement(By.id("nonInteractableElement")).sendKeys("Test"); 
// Это вызовет ElementNotInteractableException
```

**`ElementNotSelectableException`** — возникает, когда **веб-элемент не может быть выбран**, но вы пытаетесь это сделать. 
> Чаще всего *происходит при взаимодействии с кнопками, чекбоксами и т.д.*
```java
driver.findElement(By.xpath("//unselectableOption")).click(); 
// Это вызовет ElementNotSelectableException
```

---
### Исключения состояния (State-based Exceptions)

Эти исключения связаны с состоянием веб-элементов или веб-страниц во время выполнения тестов.

**`ElementNotVisibleException`** — возникает, когда *элемент присутствует на странице*, **но не виден для выполнения действий.** Может быть решено с помощью ожиданий или действий для отображения элемента.

```java
driver.findElement(By.id("hiddenElement")).click(); 
// Это вызовет ElementNotVisibleException
```

**`InvalidElementStateException`** — возникает, когда эл**емент отключен (disabled) или находится в состоянии, не позволяющем выполнить указанные действия.** Например, кнопка отправки формы или выбор даты в календаре, когда требуется предварительное заполнение обязательных полей.

```java
driver.findElement(By.id("disabledInput")).sendKeys("Test"); 
// Это вызовет InvalidElementStateException
```

**`StaleElementReferenceException`** — возникает, когда ==веб-элемент больше не доступен в DOM==, так как **был удален или находится в нестабильном состоянии**. 
> Это одно из распространенных исключений из-за динамической природы веб-элементов. 
> 
> Может быть обработано путем поиска элементов с помощью XPath.

```java
WebElement oldElement = driver.findElement(By.id("oldElement"));
// DOM изменяется
oldElement.click(); // Это вызовет StaleElementReferenceException
```

---
### Исключения таймаута и задержки (Timeout and Delay Exceptions)

Эти исключения возникают при использовании функций ожидания для поиска или выполнения действий над веб-элементами.

**`TimeoutException`** — возникает, когда **действие не выполняется в течение заданного периода времени.** Значение таймаута должно быть установлено разумно, чтобы не задерживать выполнение тестового скрипта.

```java
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(5));
wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("delayedElement"))); 
// Это может выбросить TimeoutException
```

---
### Исключения навигации (Navigation Issues)

Эти исключения возникают при навигации между страницами или переключении контекста.

**`NoSuchWindowException`** — возникает при выполнении действий, таких как переключение на другое окно или перемещение окна, когда окно недоступно или не существует.

```java
driver.switchTo().window("nonExistentWindowHandle"); 
// Это вызовет NoSuchWindowException
```

**`NoAlertPresentException`** — возникает, когда всплывающие окна (alert, prompt, confirmation) недоступны, но вы пытаетесь к ним обратиться. Это могут быть JavaScript-окна. Иногда алерты требуют больше времени для загрузки, JavaScript заблокирован на стороне браузера, или окно уже закрыто.

```java
driver.switchTo().alert(); // Это вызовет NoAlertPresentException, если алерт отсутствует
```

---
### Исключения поиска и селекторов (Selector and Search Issues)

Когда указанные веб-элементы на странице не найдены, вы можете увидеть следующие исключения.

**`NoSuchElementException`** — одно из самых распространенных исключений при поиске веб-элемента на странице. Возникает, когда указанный **элемент отсутствует на странице.** Причины: *неверный локатор*, элемент не соответствует доступному на странице, или *элемент загружается дольше и недоступен в момент поиска*.

```java
driver.findElement(By.id("nonExistentElement")); 
// Это вызовет NoSuchElementException
```

**`InvalidSelectorException`** — похоже на `NoSuchElementException`. Возникает, когда *указанный селектор недействителен или динамически изменяется.*

```java
driver.findElement(By.xpath("///invalidXPath")); 
// Это вызовет InvalidSelectorException
```

**`NoSuchFrameException`** — возникает, когда указанный фрейм не найден на веб-странице.

```java
driver.switchTo().frame("nonExistentFrame"); 
// Это вызовет NoSuchFrameException
```

---
### Исключения выполнения JavaScript (JavaScript Execution Exceptions)

Это исключение возникает при выполнении JavaScript-кода, связанного с веб-страницей.

```java
((JavascriptExecutor) driver).executeScript("invalidJavaScript()"); 
// Это вызовет JavascriptException
```

---
### Исключения сессии (Session Exceptions)

Когда сессия истекает или становится недействительной, Selenium WebDriver выбрасывает `InvalidSessionIdException`.

```java
driver.get("http://example.com");
// Предположим, сессия завершилась по какой-то причине
driver.getTitle(); // Это вызовет InvalidSessionIdException
```

---
### Исключения конфигурации драйвера и возможностей (Driver Configuration and Capability Exceptions)

Это исключение возникает **при неправильной конфигурации или неподдерживаемых функциях между WebDriver и целевым браузером.** Это базовый класс исключений Selenium WebDriver, и все остальные исключения включены в этот класс.

```java
driver.get("httt://invalidUrl"); // Это может выбросить WebDriverException из-за неверного формата URL
```
---
### Исключения ввода и аргументов (Input and Argument Exceptions)

Эти исключения связаны с входными данными или аргументами, передаваемыми WebDriver.

**`InvalidArgumentException`** — возникает, когда вы передаете **неверный аргумент.**

```java
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(-5)); 
// Это вызовет InvalidArgumentException из-за отрицательного времени
```

---
### Исключения алертов и всплывающих окон (Alert and Pop-up Exceptions)

Это исключение **связано со всплывающими окнами или алертами.** Во время выполнения теста появляется неожиданное всплывающее окно, и выбрасывается `UnexpectedAlertPresentException`.

```java
driver.get("http://example.com");
// Предположим, здесь появился неожиданный алерт
driver.findElement(By.id("someElement")).click(); 
// Это вызовет UnexpectedAlertPresentException, если не обработано
```

---
### Исключение скриншотов (Screenshot Exception)

Это исключение возникает, когда вы даете инструкцию Selenium WebDriver **сделать скриншот, но он не может его получить.**

```java
((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE); 
// Это может выбросить ScreenshotException, если создание скриншота не удалось
```

---
### Исключение движения и действий (Movement and Action Exception)

Это исключение связано с действиями мыши. Когда м**ышь пытается выйти за пределы границы, возникает** `MoveTargetOutOfBoundsException`.

```java
Actions actions = new Actions(driver);
actions.moveToElement(someElement, -1, -1).perform(); 
// Это вызовет MoveTargetOutOfBoundsException
```

---
### Исключения возможностей браузера и поддержки (Browser Capability and Support Exception)

Следующие исключения связаны **с неподдерживаемыми функциями** или возможностями браузера.

**`InsecureCertificateException`** — возникает, когда сайт, на который вы переходите, имеет недействительный или просроченный сертификат TLS.

```java
driver.get("https://insecure-certificate-website.com"); 
// Это может выбросить InsecureCertificateException
```

**`ImeNotAvailableException`** — возникает, когда IME (Input Method Engine) не поддерживается, обычно из-за отсутствия библиотек или компонентов уровня ОС.

```java
driver.manage().ime().activateEngine("IME_ENGINE"); 
// Это вызовет ImeNotAvailableException, если поддержка IME недоступна
```

**`ImeActivationFailedException`** — возникает, когда не удается активировать движок метода ввода (IME). Обычно связано с японскими, китайскими или многобайтовыми символами.

```java
driver.manage().ime().activateEngine("Invalid_IME_ENGINE"); 
// Это вызовет ImeActivationFailedException
```

---
### Исключения атрибутов и свойств (Attribute and Property Exception)

Когда вы пытаетесь получить атрибуты или свойства элемента, и эти атрибуты недоступны, возникает это исключение.

```java
String attributeVal = driver.findElement(By.id("elementWithoutAttribute"))
    .getAttribute("nonExistentAttribute"); 
// Это может выбросить NoSuchAttributeException
```

---
### Исключения обработки cookie (Cookie Handling Exception)

Исключения, возникающие при инициализации или обработке cookie в тестовом сценарии.

**`InvalidCookieDomainException`** — возникает, когда вы пытаетесь добавить cookie для другого домена, а не для текущего URL.

```java
Cookie cookie = new Cookie("test", "test123", "wrong-domain.com");
driver.manage().addCookie(cookie); 
// Это вызовет InvalidCookieDomainException
```

**`UnableToSetCookieException`** — возникает, когда Selenium WebDriver не может установить новый cookie.

```java
Cookie invalidCookie = new Cookie("name", "value", "invalid-path");
driver.manage().addCookie(invalidCookie); 
// Это вызовет UnableToSetCookieException
```

---
### Исключения обработки окон (Window Handling Exceptions)

Эти исключения возникают при переключении или работе с окнами браузера или вкладками.

**`NoSuchWindowException`** — возникает, когда окно недоступно при попытке переключения или перемещения.

```java
driver.switchTo().window("nonExistentWindowHandle"); 
// Это вызовет NoSuchWindowException
```

**`NoSuchContextException`** — возникает при тестировании мобильных приложений, когда переключение контекста не происходит.

```java
driver.context("NonExistentContext"); 
// Это может выбросить NoSuchContextException в мобильной автоматизации
```
---
### Исключения состояния элемента (Element State Exceptions)

Исключения, основанные на состоянии веб-элемента: доступен ли он для выбора, видим или интерактивен.

**`ElementNotInteractableException`** — возникает при попытке клика или ввода, когда элемент недоступен для взаимодействия, даже если он присутствует в DOM.

```java
driver.findElement(By.id("hiddenElement")).click(); 
// Это вызовет ElementNotInteractableException
```

**`ElementNotSelectableException`** — возникает при работе с радиокнопками и чекбоксами, когда элемент не может быть выбран, или при попытке выбрать невыбираемый элемент (например, div или span).

```java
driver.findElement(By.id("divElement")).click(); 
// Это может выбросить ElementNotSelectableException
```

**`ElementNotVisibleException`** — возникает при попытке выполнить действие над элементом, который присутствует на странице, но не виден или скрыт.

```java
driver.findElement(By.id("invisibleElement")).click(); 
// Это вызовет ElementNotVisibleException
```

**`InvalidElementStateException`** — возникает, когда элемент отключен (disabled); например, текстовое поле отключено, и вы пытаетесь в него писать.

```java
driver.findElement(By.id("disabledTextBox")).sendKeys("text"); 
// Это вызовет InvalidElementStateException
```

---
### Исключения сервера и ответа (Server and Response Exceptions)

Исключения, которые сервер возвращает в ответ на запросы Selenium WebDriver.

**`ErrorInResponseException`** — возникает, когда вы получаете сообщение об ошибке от сервера. Это одно из распространенных исключений при связи с удаленным сервером. 

Некоторые коды ошибок:
- 400 – BadRequest
    
- 401 – Unauthorized
    
- 403 – Forbidden
    
- 405 – MethodNotAllowed
    
- 409 – Conflict
    
- 500 – InternalServerError
    

**`ErrorHandler.UnknownServerException`** — возникает, когда нет информации о происхождении ошибки, возвращенной сервером. Это ответ на все нераспознанные ошибки сервера.

---
### Другие исключения (Other Exceptions)

Некоторые исключения не так часто наблюдаются во время выполнения тестов.

**`UnexpectedTagNameException`** — возникает, когда указанный тег не соответствует ожидаемому типу тега, связанному с элементом.
```java
WebElement checkBox = driver.findElement(By.id("aDivOrSpanID"));
Select dropdown = new Select(checkBox); 
// Это вызовет UnexpectedTagNameException, так как Select ожидает тег <select>
```

**`UnknownMethodException`** — возникает, когда Selenium WebDriver не распознает команды, определенные в тестовом скрипте.

# Обработка исключений в Selenium

После рассмотрения всех исключений и причин их возникновения, давайте перейдем к способам их обработки. Процесс или метод продолжения выполнения тестового скрипта даже после возникновения исключения из-за неожиданных событий или условий называется **обработкой исключений**.

---
## Почему обработка исключений важна в Selenium WebDriver?

**Устойчивые скрипты:** Веб-приложения динамичны. Веб-элементы могут загружаться с задержкой или не загружаться вовремя, сервисы могут давать сбои, и то, что работало вчера, может не работать сегодня. Без правильной обработки исключений малейший сбой может привести к падению теста. Обработка исключений позволяет скриптам выдерживать неожиданные сценарии, делая их более устойчивыми.

**Информативная обратная связь:** Когда скрипт необъяснимо падает, вам нужна детальная информация в логах, чтобы понять, где и что пошло не так. Обработка исключений предоставляет эту информацию, направляя вас прямо к источнику проблемы и экономя время на отладку.

**Условное выполнение:** Вы можете принимать решения, перехватывая исключения в тестовом скрипте. Например, если ссылка не найдена, можно пропустить её и искать другую, так как ссылка может требовать предварительных действий или была удалена.

---
## Обработка исключений

Когда в автоматизированном тестовом скрипте возникает исключение, нормальный поток выполнения останавливается, что приводит к ошибке. 

Эта ошибка может быть исключением времени выполнения или WebDriver-исключением. 

Selenium поддерживает методы `try-catch`, используемые в Java для обработки исключений.

---
### Элемент не найден с использованием try-catch

В Java вы используете ключевые слова `try` и `catch` для перехвата любых исключений, которые могут возникнуть. 
Этот метод объединяет два ключевых слова, каждое со своим блоком кода. Блок `try` — это начальный блок, содержащий код, в котором вы ожидаете возникновение исключения, тогда как блок `catch` содержит код, выполняемый при возникновении исключения.

В следующем примере `try-catch` ожидается исключение, возникающее, к**огда элемент не найден на веб-странице.**

```java
try {
    WebElement element = 
	    driver.findElement(By.id("optionalElement"));
    element.click();
} catch (NoSuchElementException e) {
    System.out.println("Элемент не найден: " + e.getMessage());
}
```

Функция `findElement()` выбрасывает `NoSuchElementException`, когда элемент недоступен на веб-странице. В блоке `try` вы определяете код для поиска элемента; в блоке `catch` вы определяете оператор вывода, который выполняется при возникновении этого исключения. Этот метод позволяет скрипту выполняться независимо от исключения, которое может возникнуть.

> **Примечание:** Код, написанный в блоке `try-catch`, также называется **защищенным кодом (protected code)**.

Этот подход идеален для опциональных веб-элементов на странице, когда их отсутствие не приводит к падению теста.

---
### Исключение таймаута с использованием try-catch-finally

Этот метод похож на `try-catch`; единственное отличие — наличие дополнительного блока кода для ключевого слова `finally`. Этот блок выполняется **независимо от того, возникло ли исключение**. Давайте посмотрим, как можно определить исключение таймаута в следующем блоке `try-catch-finally`.

```java
try {
    WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
    wait.until(
	    ExpectedConditions.visibilityOfElementLocated(
		    By.id("elementId")
		)
	);
} catch (TimeoutException e) {
    System.out.println("Элемент не появился в течение 10 секунд: " + e.getMessage());
} finally {
    driver.quit();
}
```
Исключение таймаута используется для ожидания появления элемента на веб-странице. Когда указанное время ожидания истекает, возникает исключение таймаута, которое упоминается в блоке `try` вместе с сообщением в блоке `catch`. Блок `finally` содержит код для закрытия WebDriver независимо от того, возникло ли исключение. Таким образом, вы можете обрабатывать любые исключения, возникающие на веб-странице, с помощью `try-catch-finally`.

---
### Исключение устаревшего элемента (Stale Element) с использованием try-catch-finally и throw

Давайте используем `try-catch-finally` с `throw` из языка Java для обработки исключения устаревшего элемента. Это исключение может возникнуть, когда веб-элемент становится устаревшим из-за перезагрузки страницы или обновления динамического контента. Вы можете выбросить пользовательское исключение с помощью ключевого слова `throw`.

```java
try {
    WebElement element = 
	    driver.findElement(By.id("dynamicElement"));
    element.click();
} catch (StaleElementReferenceException e) {
    System.out.println("Ссылка на устаревший элемент: " + e.getMessage());
    throw new RuntimeException("Ошибка из-за ссылки на устаревший элемент.");
} finally {
    System.out.println("Действия по очистке, если есть.");
}
```

Структура `try-catch-finally` остается той же. Ключевое слово `throw` было добавлено для выбрасывания пользовательского исключения. Это критически важно для тестирования в динамических сценариях, где веб-элементы в DOM могут слишком часто меняться.

---
### Обработка различных исключений с использованием множественных блоков catch

Когда у вас есть различные исключения, которые могут возникнуть при взаимодействии с веб-страницей, вам нужен метод для обработки такого механизма. Это можно сделать с помощью множественных блоков `catch`. Каждый блок представляет разные исключения, позволяя обрабатывать их отдельно. Следующий фрагмент кода обрабатывает различные исключения.

```java
try {
    WebElement element = 
	    driver.findElement(By.id("someElement"));
    element.click();
} catch (NoSuchElementException e) {
    System.out.println("Элемент не найден: " + e.getMessage());
} catch (StaleElementReferenceException e) {
    System.out.println("Ссылка на устаревший элемент: " + e.getMessage());
} catch (TimeoutException e) {
    System.out.println("Операция превысила таймаут: " + e.getMessage());
} finally {
    driver.quit();
}
```

В этом примере использованы множественные исключения, такие как элемент не найден, устаревший элемент и исключение таймаута, записанные в каждом блоке `catch` отдельно. Вы также использовали блок `finally`, когда WebDriver закрывается, сохраняя чистую тестовую среду. Это может использоваться в случаях, когда во время тестирования может возникнуть множество сбоев.

### Обработка пользовательских исключений

Вы можете настроить свою технику обработки исключений в соответствии с требованиями теста. Ниже показана настраиваемая обработка исключений.

```java
try {
    // Взаимодействия с Selenium
} catch (Exception e) {
    throw new CustomSeleniumException("Пользовательское сообщение", e);
} finally {
    // Действия по очистке
}
public class CustomSeleniumException extends Exception {
    public CustomSeleniumException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

Эта пользовательская обработка исключений помогает инкапсулировать больше информации об ошибке или создать более стандартизированный способ обработки исключений для тестовых наборов. Это может быть особенно актуально в крупных проектах или фреймворках, где вам нужно обрабатывать различные типы исключений единообразно. Определение пользовательских исключений предоставляет более детальную информацию об ошибке, упрощая ее понимание и отладку.

Эти примеры помогают обрабатывать различные исключения Selenium в Java, которые возникают во время автоматизированных веб-тестов, связанных с различными сценариями.

## Лучшие практики обработки исключений

Ниже приведены некоторые лучшие практики для написания обработки исключений в Selenium.

**Отображение информации об исключении.** Существует три метода, с помощью которых можно получить информацию о возникшем исключении:

- **`printStackTrace()`** — выводит информацию, такую как стек-трейс, имя исключения и его описание. В основном используется для отладки, так как отображает последовательность вызовов методов, которые привели к исключению.
    
- **`toString()`** — отображает имя исключения и краткое описание. Обычно используется для создания логов или отображения краткой информации об ошибке.
    
- **`getMessage()`** — возвращает детальную информацию в виде сообщения о конкретной ошибке.
    

Вы можете логировать информацию, используя любой из этих методов.

---

**Перехватывайте максимально конкретное исключение.** Старайтесь перехватывать конкретные исключения, чтобы понимать причину и обрабатывать ее соответствующим образом.

---

**Включайте блок `finally` для очистки ресурсов.** Используйте блок `finally` для освобождения ресурсов, таких как WebDriver, независимо от того, возникло ли какое-либо исключение.

---

**Внедряйте пользовательские исключения для ясности и согласованности.** Пользовательские исключения пригодятся для добавления контекста и стандартизации обработки ошибок в сложных тестовых проектах.

---

**Обрабатывайте исключения корректно.** Когда тестовый скрипт падает, необходимо убедиться, что информация об ошибке ясна и лаконична, чтобы упростить устранение неполадок.

---

**Рассмотрите механизм повторных попыток для транзиентных ошибок.** Для элементов на веб-странице, которые часто меняются, что приводит к `StaleElementReferenceException`, механизм повторных попыток делает тестовые сценарии более устойчивыми в новую динамическую эру.

---

**Избегайте исключений с помощью `findElements` и ожиданий.** Используйте `driver.findElements()` вместо `driver.findElement()`, чтобы предотвратить исключения, когда элементы не найдены, так как `findElements()` возвращает список. Комбинируйте с явными ожиданиями, чтобы убедиться, что элементы загружены. Этот подход проверяет наличие элемента, проверяя, что размер возвращенного списка не меньше единицы, что позволяет безопасно взаимодействовать без исключений:

```java
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
boolean isElementPresent = wait.until((WebDriver d) -> 
    d.findElements(locator).size() >= 1
);
if (isElementPresent) {
    // Элемент присутствует; действия могут быть выполнены безопасно.
}
```

Эта техника предлагает надежный способ проверки наличия элемента без возникновения `NoSuchElementException`, повышая стабильность скрипта.
