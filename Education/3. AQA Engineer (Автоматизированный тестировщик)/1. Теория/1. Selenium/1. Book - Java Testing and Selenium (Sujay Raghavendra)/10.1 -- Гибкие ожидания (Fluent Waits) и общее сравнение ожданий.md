# Гибкие ожидания (Fluent Waits)


> [!NOTE] Тонка настройка ожидания
> **Гибкое ожидание (Fluent Wait)** в Selenium — это тип явного ожидания, который предоставляет расширенные возможности ожидания. 
> 
> Оно позволяет вам установить максимальное время ожидания условия, а также частоту проверки условия. 

Кроме того, вы можете игнорировать определенные типы исключений во время ожидания, что делает его более гибким, чем стандартный `WebDriverWait`.

Допустим, вы хотите дождаться появления элемента, но ожидаете, что это может занять некоторое время, и вы не хотите проверять слишком часто. Ниже показано, как можно настроить гибкое ожидание.

```java
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.firefox.FirefoxDriver;
import org.openqa.selenium.support.ui.FluentWait;
import org.openqa.selenium.NoSuchElementException;
import java.time.Duration;
import java.util.function.Function;
public class SeleniumFirefoxFluentWaitExample {
    public static void main(String[] args) {
        System.setProperty(
	        "webdriver.gecko.driver", 
	        "путь/к/geckodriver");
        
        WebDriver driver = new FirefoxDriver();
        
        try {
            driver.get("http://example.com");
            
            // Определение экземпляра FluentWait
            FluentWait<WebDriver> fluentWait = new FluentWait<WebDriver>(driver)
	            // Общее время ожидания
                .withTimeout(Duration.ofSeconds(30))      
                // Частота проверки условия
                .pollingEvery(Duration.ofSeconds(5))      
                // Игнорирование NoSuchElementException
                .ignoring(NoSuchElementException.class)   
                
                .withMessage("Элемент не найден в течение 30 секунд");
            
            // Использование FluentWait
            WebElement elementToTypeIn = fluentWait.until(
            new Function<WebDriver, WebElement>() 
            {
                public WebElement apply(WebDriver webDriver) {
                    return webDriver
	                    .findElement(By.id("elementId"));
                }
            });
            
            elementToTypeIn.sendKeys("Hello, World!");
            
        } finally {
            driver.quit();
        }
    }
}
```

В этом примере `FluentWait` настроен на ожидание до 30 секунд для появления элемента с проверкой каждые 5 секунд. Он игнорирует `NoSuchElementException`, которое выбрасывается `driver.findElement()`, если элемент не найден на странице. Пользовательское сообщение включается в исключение, выбрасываемое при превышении таймаута.

Этот подход полезен, когда вы имеете дело с элементами, время загрузки которых может сильно варьироваться, или когда страница содержит много динамического контента. Используя гибкое ожидание, вы можете создать высоконастраиваемую стратегию ожидания, адаптированную к конкретным потребностям приложения.

---
### Ключевые особенности гибкого ожидания (Fluent Wait)

|Особенность|Описание|
|---|---|
|**Настраиваемая частота опроса**|Вы можете определить частоту проверки условия. Это полезно для уменьшения количества проверок в сценариях, где элемент загружается долго.|
|**Таймаут**|Вы можете установить максимальное время ожидания условия.|
|**Игнорирование исключений**|Вы можете указать одно или несколько исключений, которые следует игнорировать, если они возникают во время опроса условия.|
|**Пользовательское сообщение**|Вы можете предоставить собственное сообщение о таймауте, которое может быть полезно для отладки.|

## Выбор правильного ожидания

Выбор между неявными, явными и гибкими ожиданиями зависит от конкретных требований и сложности веб-элементов и их поведения в тестовой среде. 

Давайте обсудим работу, использование, настройку, поведение и ограничения для каждого типа ожидания, чтобы помочь выбрать наилучший для ваших требований.

---
### Неявное ожидание (Implicit Wait)

- **Как работает:** Неявное ожидание указывает WebDriver ==ждать определенное время перед выбрасыванием== `NoSuchElementException`, если элемент не найден. Это ожидание устанавливается глобально на время жизни экземпляра WebDriver и применяется ко всем поискам элементов.
    
- **Когда использовать:** Используйте его, когда у вас есть относительно небольшая, фиксированная задержка, которую вы можете применить ко всем поискам элементов в тестовом скрипте.
    
- **Настройка:** Устанавливается на весь срок жизни объекта WebDriver. После установки применяется ко всем вызовам `findElement` и `findElements`.
    
- **Поведение:** Драйвер опрашивает DOM через регулярные интервалы, пока элемент не будет найден или не будет достигнут таймаут.
    
- **Ограничения:** Не может использоваться для более сложных условий. Кроме того, если установлен слишком большой таймаут, это может вызвать ненужные задержки в выполнении теста.
    
- **Пример кода:**
    

```java
driver.manage()
	.timeouts().implicitlyWait(Duration.ofSeconds(10));
```

---
### Явное ожидание (Explicit Wait)

- **Как работает:** Явное ожидание указывает WebDriver ==ждать определенные условия== (`ExpectedConditions`) ==или до истечения максимального времени== перед выбрасыванием `TimeoutException`. Явное ожидание специфично для конкретного элемента и его условия.
    
- **Когда использовать:** Используйте его, когда вам нужно дождаться определенных условий на определенных элементах, например, ожидание, пока элемент станет кликабельным, видимым или пока не появится определенный текст.
    
- **Настройка:** Устанавливается для каждого конкретного экземпляра, где это необходимо. Вы можете определить `WebDriverWait` вместе с конкретным условием.
    
- **Поведение:** Драйвер ожидает выполнения указанного условия перед продолжением. Если условие не выполняется в течение таймаута, выбрасывается `TimeoutException`.
    
- **Ограничения:** Требует больше шаблонного кода по сравнению с неявными ожиданиями и должен быть реализован для каждого конкретного условия и элемента.
    
- **Пример кода:**
    

```java
WebDriverWait wait = new WebDriverWait(
	driver, 
	Duration.ofSeconds(10)
);
WebElement element = 
	wait.until(
		ExpectedConditions.visibilityOfElementLocated(
			By.id("someId")
		)
	);
```

---
### Гибкое ожидание (Fluent Wait)

- **Как работает:** Гибкое ожидание позволяет более сложную настройку условий ожидания. Вы можете установить максимальное время ожидания условия, частоту проверки условия и игнорировать определенные типы исключений во время ожидания.
    
- **Когда использовать:** Идеально для более сложных сценариев, где вам нужно настроить частоту опроса или игнорировать определенные типы исключений во время ожидания (например, ожидание Ajax-элементов).
    
- **Настройка:** Вы можете настроить гибкое ожидание, создав экземпляр `FluentWait`, установив таймаут, частоту опроса и исключения для игнорирования.
    
- **Поведение:** Гибкое ожидание проверяет условие с указанными интервалами опроса и продолжается, пока условие не будет выполнено или не истечет таймаут. Оно игнорирует указанные исключения во время процесса опроса.
    
- **Ограничения:** Более сложен в настройке по сравнению с явным ожиданием. Может быть избыточным для более простых условий, где стандартных `ExpectedConditions` достаточно.
    
- **Пример кода:**

```java
FluentWait<WebDriver> wait = new FluentWait<WebDriver>(driver)
    .withTimeout(Duration.ofSeconds(30))
    .pollingEvery(Duration.ofSeconds(5))
    .ignoring(NoSuchElementException.class);
WebElement element = wait.until(new Function<WebDriver, WebElement>() {
    public WebElement apply(WebDriver driver) {
        return driver.findElement(By.id("someId"));
    }
});
```

## Сравнительный анализ неявных, явных и гибких ожиданий

В таблице 10-1 представлено сравнение неявных, явных и гибких ожиданий в Selenium.

**Таблица 10-1. Сравнение типов ожиданий**

|Критерий|Неявные ожидания|Явные ожидания|Гибкие ожидания|
|---|---|---|---|
|**Область применения**|Глобально для всех веб-элементов|Специфично для конкретных элементов или условий|Специфично, с настраиваемыми интервалами опроса и таймаутом|
|**Условия ожидания**|Ожидание появления элементов в DOM|Ожидание конкретных условий (видимость, кликабельность)|Ожидание пользовательских условий с гибкими интервалами проверки|
|**Гибкость**|Менее гибкий; одинаковое время ожидания для всех элементов|Более гибкий; разные условия для разных элементов|Наиболее гибкий; настраиваемые условия, интервалы и таймауты|
|**Частота проверки условия**|Нет контроля над частотой|Фиксированная частота, определенная в ExpectedConditions|Настраиваемая частота проверки условия|
|**Обработка исключений**|Нет специального механизма обработки исключений|Может обрабатывать некоторые исключения (например, NoSuchElementException)|Позволяет детальную обработку исключений в течение периода ожидания|
|**Настройка таймаута**|Фиксированный таймаут на время жизни WebDriver|Фиксированный таймаут для каждого условия|Настраиваемый максимальный таймаут и частота опроса|
|**Сложность**|Прост в реализации и использовании|Сложнее, чем неявные, но в целом понятен|Наиболее сложный, предоставляющий детальный контроль над условиями ожидания|
|**Сценарий использования**|Полезен для простых, статичных страниц, где элементы загружаются примерно одинаково|Идеален для динамического контента, где ожидаются конкретные условия|Лучше всего подходит для высокодинамичных и непредсказуемых веб-элементов|

Эта таблица выделяет ключевые различия, чтобы помочь вам сделать осознанный выбор о том, какой тип ожидания использовать в сценариях тестирования Selenium.

## Лучшие практики использования ожиданий в автоматизации тестирования Selenium

Эффективное использование ожиданий является критически важным аспектом автоматизации тестирования Selenium, так как это обеспечивает надежность и устойчивость тестов. Вот некоторые лучшие практики использования ожиданий в Selenium.

---

**Отдавайте предпочтение явным ожиданиям перед неявными.** Используйте явные ожидания (`WebDriverWait` с `ExpectedConditions`), так как они более надежны для сложных условий. Они позволяют вам ожидать конкретных условий на конкретных элементах.

---

**Избегайте использования фиксированных пауз (`Thread.sleep()`).** Фиксированные паузы заставляют тесты ждать заранее определенное количество времени, что может быть неэффективно и приводить к увеличению времени выполнения тестов. Они не учитывают фактическое состояние элементов.

---

**Будьте внимательны к настройкам таймаута.** Устанавливайте реалистичные таймауты, учитывая скорость сети, время ответа приложения и общую производительность. Избегайте установки слишком больших таймаутов, так как это может замедлить ваш тестовый набор.

---

**Используйте гибкое ожидание для более сложных условий.** При работе с элементами с сильно непредсказуемым временем загрузки используйте гибкое ожидание. Оно позволяет настраивать частоту опроса и игнорировать определенные типы исключений, делая тесты более устойчивыми.

---

**Минимизируйте использование неявных ожиданий.** Неявные ожидания устанавливаются глобально и применяются ко всем поискам элементов. Хотя они просты в использовании, они могут вызывать непреднамеренные задержки. Используйте их экономно и только тогда, когда у вас есть постоянно небольшая задержка, применимая ко всем поискам элементов.

---

**Комбинируйте ожидания с умом.** Будьте осторожны при комбинировании различных типов ожиданий, так как это может привести к непредсказуемому времени ожидания или даже таймаутам. Понимайте, как различные ожидания работают вместе в вашем конкретном контексте.

---

**Ожидайте полной загрузки страницы и завершения Ajax-вызовов.** Убедитесь, что страница полностью загружена и все Ajax-вызовы завершены перед взаимодействием с элементами. Это может быть достигнуто с помощью пользовательских `ExpectedConditions` или выполнения JavaScript.

---

**Используйте ожидания для масштабируемости и поддерживаемости тестов.** Внедрение правильных ожиданий делает тесты более масштабируемыми и поддерживаемыми, так как это уменьшает нестабильность, вызванную проблемами синхронизации.

---

**Создавайте пользовательские условия ожидания при необходимости.** Иногда встроенных `ExpectedConditions` может быть недостаточно для ваших нужд. В таких случаях создавайте пользовательские условия ожидания для обработки уникальных сценариев, специфичных для вашего приложения.

---

**Регулярно пересматривайте и корректируйте стратегии ожидания.** По мере развития вашего приложения должны развиваться и ваши стратегии ожидания. Регулярно пересматривайте и корректируйте их в соответствии с текущим поведением приложения.

---

**Документируйте вашу стратегию ожидания.** Убедитесь, что ваш подход к ожиданиям хорошо документирован. Это помогает поддерживать согласованность в тестовом наборе и облегчает понимание подхода новым членам команды.

Следуя этим лучшим практикам, вы можете создавать тесты Selenium, которые не только точны с точки зрения функционального тестирования, но и эффективны и надежны в своем выполнении.
