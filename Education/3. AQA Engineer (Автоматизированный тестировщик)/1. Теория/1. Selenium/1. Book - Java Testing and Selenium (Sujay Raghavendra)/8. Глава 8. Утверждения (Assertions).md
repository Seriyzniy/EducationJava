В этой главе рассматриваются фундаментальные концепции, техники и лучшие практики использования утверждений (assertions) в Selenium. Утверждения — это надежный инструмент для проверки поведения и функциональности веб-приложений во время автоматизированного тестирования.

Начиная с введения в утверждения, вы узнаете, что это такое и почему они имеют огромное значение в Selenium. 

Затем вы погрузитесь ==в два основных типа утверждений==: **жесткие (hard)** и **мягкие (soft)**.

Далее вы изучите набор методов утверждений, предоставляемых Selenium, которые необходимы для сравнения и проверки ожидаемых результатов с фактическими. Вы также разберете обработку ошибок утверждений: что происходит при их падении и как управлять такими ситуациями с логированием и отчетностью.

Особое внимание уделяется **пользовательским утверждениям** — вы узнаете, как создавать собственные методы проверок под специфические требования приложения.

В конце главы рассматриваются типичные ошибки при работе с утверждениями и стратегии их предотвращения.

---
# Что такое утверждения (Assertions)?

**Утверждения** в Selenium — ==это проверки==, которые вы встраиваете в автоматизированные тестовые скрипты, чтобы убедиться, что определенные условия выполняются во время работы веб-приложения. 

Эти условия могут включать широкий спектр критериев: проверка наличия элемента на странице, соответствие текста ожидаемому, совпадение URL с заданным шаблоном и т.д.

---
# Зачем нужны утверждения?

Утверждения — это не просто строки кода; они являются неотъемлемой частью эффективности и надежности автоматизированных тестов.

|Причина|Описание|
|---|---|
|**Проверка ожидаемого поведения**|Утверждения действуют как механизмы контроля качества, позволяя убедиться, что приложение ведет себя как задумано и соответствует заданным критериям.|
|**Эффективность автоматизации**|Без утверждений вам потребовалось бы ручное вмешательство для подтверждения прохождения теста, что противоречит цели автоматизации.|
|**Обнаружение ошибок**|Утверждения помогают выявлять проблемы на ранних стадиях тестирования. Если утверждение падает, это указывает на проблему в приложении или тестовом скрипте.|
|**Документация**|Утверждения служат документацией внутри тестовых скриптов, поясняя, какие условия проверяются и что считается успешным тестом.|

---
# Жесткие утверждения (Hard Assertions)

> [!NOTE] "Если утверждение падает - падает тест"
> **Жесткие утверждения** — это строгие контрольные точки в ваших Selenium-тестах. 
> 
> Когда жесткое утверждение **падает (fail)**, выполнение тестового скрипта **немедленно останавливается**, и весь тест помечается как проваленный.

Представьте их как *условия, которые* **обязательно** *должны быть выполнены* для продолжения теста. Например, если вы проверяете наличие кнопки "Отправить" на странице, и она не найдена, тест останавливается, и вы получаете сообщение об ошибке.

---
## Пример жесткого утверждения

**HTML-страница (`example.html`):**
```html
<!DOCTYPE html>
<html>
<head>
    <title>Пример страницы</title>
</head>
<body>
    <h1>Добро пожаловать в пример утверждений Selenium</h1>
    <p id="textElement">Это образец абзаца.</p>
    <button id="submitButton">Отправить</button>
</body>
</html>
```

**Java-код с жесткими утверждениями:**
```java
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.Assert;
public class HardAssertionsExample {
    public static void main(String[] args) {
        System.setProperty(
	        "webdriver.chrome.driver", "путь/к/chromedriver");
	        
        WebDriver driver = new ChromeDriver();
        driver.get("file:///путь/к/example.html");
        
        WebElement textElement = 
	        driver.findElement(By.id("textElement"));
        
        WebElement submitButton = 
	        driver.findElement(By.id("submitButton"));
	        
        // Жесткие утверждения
        Assert.assertEquals(
	        textElement.getText(), 
	        "Это образец абзаца."
	    );
        Assert.assertTrue(
	        submitButton.isDisplayed()
	    );
        driver.quit();
    }
}
```

Если **любое** из этих утверждений упадет, тест немедленно остановится.

# Мягкие утверждения (Soft Assertions)

> [!NOTE] "Если упало утверждение, НИЧЕГО СТРАШНОГО, работаем дальше"
> **Мягкие утверждения** (часто называют **Verify**) — это более гибкий подход. 
> 
> Когда мягкое утверждение падает, тест **продолжает выполняться**, собирая информацию обо всех ошибках для последующего анализа.

Это полезно, когда вы хотите проверить множество элементов на странице, и падение одного из них не должно останавливать весь тест. Вы сможете увидеть все проблемы в одном отчете.

---
## Пример мягкого утверждения

```java
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.asserts.SoftAssert;
public class SoftAssertionsExample {
    public static void main(String[] args) {
        System.setProperty(
	        "webdriver.chrome.driver", "путь/к/chromedriver");
        
        WebDriver driver = new ChromeDriver();
        driver.get("file:///путь/к/example.html");
        
        WebElement textElement = 
	        driver.findElement(By.id("textElement"));
        WebElement submitButton = 
	        driver.findElement(By.id("submitButton"));
	        
        // Инициализация SoftAssert
        SoftAssert softAssert = new SoftAssert();
        // Мягкие утверждения
        softAssert.assertEquals(
	        textElement.getText(), "Это образец абзаца."
	    );
        softAssert.assertTrue(submitButton.isDisplayed());
        
        // Дополнительные шаги теста...
        // ...
        // В конце теста проверяем все накопленные ошибки
        softAssert.assertAll(); // Если есть ошибки, тест будет помечен как failed
        driver.quit();
    }
}
```

**Важно:** В конце теста обязательно вызывайте `softAssert.assertAll()`, чтобы проверить все накопленные ошибки и пометить тест как проваленный, если они были.

---
# Сравнение жестких и мягких утверждений

| Характеристика                    | **Жесткие** (Hard Assertions)                            | **Мягкие** (Soft Assertions)                                     |
| --------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------- |
| **Поведение при падении**         | *Немедленная остановка теста*                            | *Продолжение выполнения теста*                                   |
| **Когда использовать**            | *Критические проверки*, без которых тест не имеет смысла | Когда *нужно собрать информацию о всех проблемах за один прогон* |
| **Обработка нескольких проверок** | Первая же ошибка останавливает тест                      | Все *ошибки собираются до конца теста*                           |
| **Отчетность**                    | Мгновенная обратная связь                                | Консолидированный отчет в конце теста                            |

# Методы утверждений в Selenium (TestNG)

|Метод|Описание|Пример|
|---|---|---|
|**`assertEquals(expected, actual)`**|Проверяет равенство двух значений|`Assert.assertEquals(title, "Ожидаемый заголовок");`|
|**`assertNotEquals(expected, actual)`**|Проверяет, что значения **НЕ** равны|`Assert.assertNotEquals(price, 0);`|
|**`assertTrue(condition)`**|Проверяет, что условие **истинно**|`Assert.assertTrue(element.isDisplayed());`|
|**`assertFalse(condition)`**|Проверяет, что условие **ложно**|`Assert.assertFalse(element.isSelected());`|
|**`assertNull(object)`**|Проверяет, что объект **равен null**|`Assert.assertNull(userData);`|
|**`assertNotNull(object)`**|Проверяет, что объект **НЕ равен null**|`Assert.assertNotNull(driver);`|
|**`fail(message)`**|Принудительно помечает тест как проваленный|`Assert.fail("Тест упал по причине...");`|

# Обработка ошибок утверждений

Когда **утверждение падает, выбрасывается исключение** `AssertionError`. 

Если его не обработать, тест останавливается.

## Что происходит при падении утверждения?
1. Выполнение теста прерывается.
    
2. Библиотека утверждений выбрасывает исключение.
    
3. Тест помечается как проваленный.
    
4. Последующие шаги после упавшего утверждения **НЕ выполняются** (в случае жестких утверждений).
    

---
## Обработка ошибок с помощью `try-catch`
```java
try {
    Assert.assertEquals(actual, expected);
} catch (AssertionError e) {
    // Логируем ошибку
    System.out.println("Утверждение упало: " + e.getMessage());
    // Делаем скриншот
    takeScreenshot(driver);
    // Выполняем восстановительные действия
    driver.navigate().refresh();
}
```

## Логирование и отчетность

**Логирование:**
```java
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

private static final Logger logger = 
	LogManager.getLogger(TestClass.class);
	
try {
    Assert.assertEquals(actual, expected);
} catch (AssertionError e) {
    logger.error("Утверждение упало: {}", e.getMessage());
}
```

**Отчетность:** Используйте фреймворки для отчетности (Allure, ExtentReports), которые автоматически захватывают информацию о падениях, делают скриншоты и формируют детальные отчеты.

## 📌 Лучшие практики использования утверждений

|Практика|Описание|
|---|---|
|**Используйте осмысленные сообщения**|Всегда добавляйте сообщения к утверждениям, чтобы было понятно, что пошло не так.|
|**Держите утверждения простыми**|Одно утверждение — одна проверка. Не смешивайте несколько проверок в одном.|
|**Группируйте связанные проверки**|Если проверки логически связаны, группируйте их в одном тестовом методе.|
|**Используйте мягкие утверждения для множественных проверок**|Когда нужно проверить много условий, используйте `SoftAssert`, чтобы увидеть все ошибки.|
|**Не забывайте `assertAll()`**|Для мягких утверждений всегда вызывайте `assertAll()` в конце теста.|
|**Логируйте ошибки**|Всегда логируйте информацию о падениях для упрощения отладки.|
|**Избегайте ложных срабатываний**|Убедитесь, что ваши проверки точны и не дают ложных положительных или отрицательных результатов.|

# Пользовательские утверждения (Custom Assertions)

Создание пользовательских методов утверждений в Selenium позволяет адаптировать проверки под специфические требования приложения и расширять функциональность встроенных библиотек утверждений. 

Это может быть ценно при выполнении сложных или доменно-специфичных проверок в автоматизированных тестах.

---
## Создание пользовательских методов утверждений

Пользовательские методы утверждений — это определяемые пользователем проверки, которые выходят за рамки стандартных методов, предоставляемых фреймворками тестирования (TestNG или JUnit).

**Шаги по созданию пользовательского утверждения:**
1. **Определите специфическое требование.** Начните с выявления уникального или сложного условия, которое требует проверки в вашем приложении. *Это может быть поведение пользовательского UI-компонента, проверка данных или специфическая бизнес-логика.*
    
2. **Напишите метод пользовательского утверждения.** Создайте новый метод, который инкапсулирует логику проверки определенного требования. *Метод должен возвращать булево значение, указывающее, выполнено ли условие.*
    
3. **Используйте пользовательское утверждение в тестах.** Внедрите метод пользовательского утверждения в ваши тестовые скрипты там, где это необходимо.
    
4. **Обрабатывайте ошибки утверждений.** Обеспечьте обработку ошибок внутри пользовательского метода: выбрасывайте исключения, логируйте информацию о сбое или выполняйте восстановительные действия.
    

---
### Пример: пользовательское утверждение для проверки возраста

Предположим, вам нужно проверить, попадает ли возраст пользователя в заданный диапазон.

```java
public class CustomAssertions {
    public static boolean isAgeInRange(int age, int minAge, int maxAge) {
        return age >= minAge && age <= maxAge;
    }
}
```

**Использование в тесте:**
```java
import org.testng.Assert;
public class TestExample {
    public static void main(String[] args) {
        int userAge = 30;
        int minValidAge = 18;
        int maxValidAge = 60;
        boolean isAgeValid = 
        
        CustomAssertions.isAgeInRange(
	        userAge, 
	        minValidAge, 
	        maxValidAge
	    );
        Assert.assertTrue(
	        isAgeValid, 
	        "Возраст пользователя не входит в допустимый диапазон.");
    }
}
```

## Расширение функциональности утверждений

==Расширение функциональности утверждений== позволяет улучшить встроенные методы утверждений, предоставляемые фреймворком, для выполнения дополнительных проверок или кастомизации отчетности.

**Шаги по расширению:**
1. **Создайте пользовательский класс утверждений.** Разработайте класс, который р*асширяет класс утверждений вашего фреймворка* (например, `org.testng.Assert` в TestNG).
    
2. **Добавьте новые методы утверждений.** Определите новые методы внутри вашего пользовательского класса.
    
3. **Используйте пользовательские утверждения.** Внедрите их в тестовые скрипты.
    
4. **Настройте отчетность.** Если ваши утверждения предоставляют дополнительные возможности логирования или отчетности, убедитесь, что они корректно фиксируются в отчетах.
    

---
### Пример: расширение Assert в TestNG с добавлением временной метки

```java
import org.testng.Assert;
import java.text.SimpleDateFormat;
import java.util.Date;
public class CustomAssert extends Assert {
    
    public static void assertTrueWithTimestamp(boolean condition, String message) {
        if (!condition) {
            String timestamp = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss").format(new Date());
            String errorMessage = "[" + timestamp + "] " + message;
            fail(errorMessage);
        }
    }
}
```

**Использование:**
```java
public class TestExample {
    public static void main(String[] args) {
        boolean condition = true; // Замените на ваше условие
        CustomAssert.assertTrueWithTimestamp(condition, "Пользовательское утверждение провалилось.");
    }
}
```

## Типичные ошибки при работе с утверждениями в Selenium

Даже опытные тестировщики и разработчики могут допускать ошибки при работе с утверждениями в Selenium. Эти ошибки приводят к ненадежным тестам, ложным срабатываниям и сложностям в поддержке.

---
### Распространенные ошибки

| Ошибка                             | Описание                                                                        | Решение                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **Недостаточное ожидание**         | Отсутствие ожидания загрузки элементов перед выполнением утверждений            | Используйте явные ожидания (`WebDriverWait`)              |
| **Недостаточное логирование**      | Отсутствие достаточной информации о падениях утверждений                        | Добавляйте осмысленные сообщения об ошибках и контекст    |
| **Использование `Thread.sleep()`** | Неэффективно и приводит к медленным и ненадежным тестам                         | ==Предпочитайте ЯВНЫЕ ОЖИДАНИЯ с жестко заданным паузам== |
| **Игнорирование исключений**       | Неправильная обработка исключений приводит к преждевременному завершению тестов | Используйте `try-catch` для graceful-обработки ошибок     |
| **Переиспользование утверждений**  | Слишком много утверждений в одном тесте усложняет поддержку                     | Фокусируйтесь на критических проверках                    |

---
## Как избегать ложных срабатываний (False Positives) и ложных отрицаний (False Negatives)

|Проблема|Описание|Решение|
|---|---|---|
|**Ложные срабатывания (False Positives)**|Утверждения падают из-за временных проблем (медленная загрузка, сеть), а не из-за реальных дефектов|Используйте явные ожидания с разумными таймаутами; внедряйте механизмы повторных попыток|
|**Ложные отрицания (False Negatives)**|Утверждения проходят, хотя дефекты существуют, или проверки написаны некорректно|Точно и полно описывайте проверки; регулярно пересматривайте утверждения при изменении приложения|

---
## Дополнительные рекомендации

**Стабильность тестовых данных:**

Убедитесь, что тестовые данные согласованы и надежны. Поддерживайте стабильный набор данных и проверяйте их перед выполнением тестов.

**Стабильность окружения:**

Контролируйте тестовое окружение, чтобы минимизировать его изменения. Документируйте любые изменения, которые могут повлиять на результаты тестов.

**Эффективная отчетность:**

Внедрите механизм отчетности, который различает истинные падения, ложные срабатывания и ложные отрицания. Используйте фреймворки отчетности, позволяющие классифицировать результаты.

# Лучшие практики использования утверждений в Selenium

## Когда использовать утверждения

Используйте утверждения в ключевых точках тест-кейсов для проверки ожидаемого поведения приложения. Это включает проверку наличия элементов, их атрибутов, текстового содержимого и других критических аспектов.

**Рекомендация:** Используйте утверждения после действий (клики, заполнение форм, навигация). Проверяйте, что ожидаемые результаты совпадают с фактическими.

---
## Простота и специфичность утверждений

Держите утверждения простыми и сфокусированными на одной проверке. Сложные утверждения сложно поддерживать и отлаживать.

**Рекомендация:** Разбивайте сложные утверждения на несколько простых, каждое из которых проверяет один аспект состояния страницы.

---
## Осмысленные сообщения об ошибках

Сообщения об ошибках должны давать ценную информацию при падении утверждений. Общие или расплывчатые сообщения затрудняют диагностику.

**Рекомендация:** Пишите сообщения, которые четко описывают, что пошло не так. Включайте информацию об ожидаемом условии и фактическом состоянии приложения.

```java
Assert.assertEquals(actualTitle, expectedTitle, 
    "Заголовок страницы не соответствует ожидаемому. " +
    "Ожидалось: '" + expectedTitle + "', фактически: '" + actualTitle + "'");
```

## Организация утверждений в тест-кейсах

Правильная организация утверждений повышает читаемость и поддерживаемость.

**Рекомендация:** Группируйте связанные утверждения вместе в хорошо структурированных методах или секциях тест-кейсов. Используйте комментарии или понятные имена для обозначения цели каждой группы.

---
## 📌 Резюме главы

|Тема|Ключевые моменты|
|---|---|
|**Пользовательские утверждения**|Создание методов проверки под специфические требования приложения|
|**Расширение утверждений**|Добавление новых методов (например, с временными метками)|
|**Типичные ошибки**|Недостаточное ожидание, плохое логирование, `Thread.sleep()`|
|**Ложные срабатывания**|Падения из-за временных проблем, а не дефектов|
|**Ложные отрицания**|Пропуск реальных проблем из-за некорректных проверок|
|**Лучшие практики**|Простота, осмысленные сообщения, группировка, правильное время использования|
