# Понимание фреймворков в деталях

*Фреймворки в автоматизации тестирования* **служат стратегическими шаблонами.** 

Они предлагают предопределенный способ организации тестов, делая их переиспользуемыми и легкими в поддержке. Фреймворки гарантируют, что ваши практики тестирования направлены не просто на выполнение работы, а на выполнение ее максимально эффективно и надежно.

# Обзор JUnit

**JUnit** — давний стандарт в мире тестирования Java, фреймворк, в первую очередь **предназначенный для модульного тестирования.** Это инструмент, на который многие полагались годами, развивающийся вместе с изменяющейся динамикой разработки программного обеспечения.

В последней итерации JUnit 5 (Jupiter) представляет собой значительный прогресс по сравнению со своими предшественниками, внося больше гибкости и функций для современных потребностей тестирования.

---
## Изучение возможностей JUnit

JUnit, фундаментальный фреймворк в тестировании Java, предлагает функции, которые установили стандарт в модульном тестировании.

- **Аннотации** — как указатели в вашем коде, направляющие процесс тестирования. Например, `@Test` указывает тестовый метод, `@BeforeEach` настраивает условия перед каждым тестом, а `@AfterEach` выполняет очистку после каждого теста.
    
- **Утверждения (Assertions)** — контрольные точки тестов, позволяющие проверять ожидаемые результаты.
    
- **Test runners** — движки, которые запускают тесты, обеспечивая выполнение тестовых наборов.
    
- **Test suites** — контейнеры, которые содержат и управляют множеством связанных тестов.
    
- **Параметризованные тесты** — позволяют запускать один и тот же тест с разными параметрами, расширяя покрытие тестами.

# Переход к TestNG: выход за пределы JUnit

**TestNG** (Test Next Generation) — это современный фреймворк тестирования, который стал основным в среде разработки Java, особенно для автоматизированного тестирования. 

Он был задуман как ответ на определенные ограничения, найденные в JUnit. 
**TestNG разработан для упрощения широкого спектра потребностей тестирования** — *от модульного до интеграционного и функционального тестирования.*

Необходимость в большей гибкости и функциональности в фреймворках тестирования Java привела к созданию TestNG. Его философия дизайна фокусируется на том, чтобы сделать процесс тестирования более эффективным, структурированным и всеобъемлющим. Это не просто альтернатива JUnit, а полноценное решение, которое выходит за пределы простого модульного тестирования, предоставляя инструменты и функции, необходимые для сложных сценариев тестирования.

На момент написания этой главы последняя версия TestNG предлагает продвинутые функции, совместимые с широким спектром инструментов разработки и тестирования.

# Аннотации и атрибуты TestNG

В TestNG аннотации — это указатели, которые направляют выполнение ваших тестовых скриптов. Они критически важны для определения структуры тестов, задания порядка выполнения и настройки поведения тестов.

---
## `@Test`: Ядро TestNG

Аннотация `@Test` **идентифицирует метод как тест TestNG**. 

Она ==имеет несколько атрибутов==, позволяющих контролировать различные аспекты поведения тестового метода.

### `priority` — приоритет выполнения
Определяет **порядок выполнения тестовых методов**. Меньшие числа выполняются раньше.

```java
@Test(priority = 1)
public void firstTest() {
    System.out.println("Первый тестовый метод");
}
@Test(priority = 2)
public void secondTest() {
    System.out.println("Второй тестовый метод");
}
```

**Когда использовать:** Когда порядок выполнения тестовых методов важен.

---
### `enabled` — включение/отключение теста

Определяет, выполняется ли тестовый метод. `false` пропускает выполнение.

```java
@Test(enabled = false)
public void disabledTest() {
    System.out.println("Этот тест не будет выполнен.");
}
```

**Когда использовать:** Чтобы временно отключить тест без удаления кода.

---
### `dependsOnMethods` — зависимость от других методов

Метод будет выполнен только ПОСЛЕ УСПЕШНОГО ВЫПОЛНЕНИЯ УКАЗАННЫХ МЕТОДОВ.

```java
@Test
public void firstTest() {
    System.out.println("Первый тест");
}

@Test(dependsOnMethods = {"firstTest"})
public void dependentTest() {
    System.out.println("Выполняется после firstTest");
}
```

**Когда использовать:** Для управления зависимостями между тестами.

---
### `groups` — группировка тестов

Назначает тестовый метод в одну или несколько групп. Удобно для запуска подмножеств тестов (например, "sanity", "regression").

```java
@Test(groups = {"sanity"})
public void sanityTest() {
    System.out.println("Часть группы sanity");
}

@Test(groups = {"regression"})
public void regressionTest() {
    System.out.println("Часть группы regression");
}
```

**Когда использовать:** Для категоризации тестов в больших проектах.

---
### `dataProvider` — поставщик данных для теста

Указывает метод, который предоставляет данные для тестового метода, обеспечивая тестирование на основе данных.

```java
@Test(dataProvider = "dataMethod")
public void dataDrivenTest(String input) {
    System.out.println("Тест с данными: " + input);
}

@DataProvider
public Object[][] dataMethod() {
    return new Object[][] {{"data1"}, {"data2"}, {"data3"}};
}
```

**Когда использовать:** Для выполнения одного теста с разными наборами данных.

---
### `expectedExceptions` — ожидаемые исключения

Указывает, что метод должен выбросить исключение. **Если указанное исключение выбрасывается, тест проходит.**

```java
@Test(expectedExceptions = ArithmeticException.class)
public void exceptionTest() {
    int i = 1 / 0; // Ожидается ArithmeticException
}
```

**Когда использовать:** При тестировании условий, которые должны вызывать исключения.

---
# Другие аннотации TestNG

В сочетании с `@Test` другие аннотации TestNG позволяют создавать комплексный и эффективный рабочий процесс тестирования.

---
## `@BeforeSuite` / `@AfterSuite`

Выполняются **ДО И ПОСЛЕ ВСЕХ ТЕСТОВ В НАБОРЕ** (suite). Используются ***для глобальной настройки и очистки ресурсов.***

```java
@BeforeSuite
public void globalSetup() {
    System.out.println(
	    "Глобальная настройка перед всеми тестами.");
}

@AfterSuite
public void globalTeardown() {
    System.out.println(
	    "Глобальная очистка после всех тестов.");
}
```

---
## `@BeforeTest` / `@AfterTest`

Выполняются **ДО И ПОСЛЕ ТЕСТОВОВ** внутри тега `<test>` в XML-конфигурации TestNG.

```java
@BeforeTest
public void setupTest() {
    System.out.println("Настройка перед группой тестов.");
}
@AfterTest
public void teardownTest() {
    System.out.println("Очистка после группы тестов.");
}
```

---
## `@BeforeClass` / `@AfterClass`

Выполняются **ДО И ПОСЛЕ ВСЕХ МЕТОДОВ ТЕКУЩЕГО КЛАССА.**

```java
@BeforeClass
public void setupClass() {
    System.out.println("Настройка перед методами класса.");
}

@AfterClass
public void teardownClass() {
    System.out.println("Очистка после методов класса.");
}
```

---
## `@BeforeMethod` / `@AfterMethod`

Выполняются **ДО И ПОСЛЕ КАЖДОГО ТЕСТОВОГО МЕТОДА**.

```java
@BeforeMethod
public void setupMethod() {
    System.out.println(
	    "Настройка перед каждым тестовым методом.");
}

@AfterMethod
public void teardownMethod() {
    System.out.println(
	    "Очистка после каждого тестового метода.");
}
```

# Тестовый пример TestNG с Selenium

Давайте создадим тестовый пример TestNG с использованием Selenium, который демонстрирует использование различных аннотаций TestNG. Этот пример предполагает, что у вас настроен Selenium в вашем Java-проекте вместе с фреймворком TestNG.

Сначала рассмотрим простой HTML-фрагмент, а затем напишем тестовый пример TestNG для взаимодействия с элементами и их проверки.

---
## Пример HTML-фрагмента

Предположим, у вас есть базовый HTML-файл с именем `example.html` со следующим содержимым:

```html
<!DOCTYPE html>
<html>
<head>
    <title>Тестовая страница</title>
</head>
<body>
    <h1>Добро пожаловать на тестовую страницу</h1>
    <button id="testButton">Нажми меня</button>
</body>
</html>
```
Этот HTML содержит простую кнопку с ID `testButton`.

---
## Написание тестового примера TestNG

Напишем тестовый пример TestNG для загрузки этого HTML-файла в браузере, поиска кнопки по её ID и выполнения действия или проверки.

```java
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.Assert;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeMethod;
import org.testng.annotations.Test;

public class ExampleHtmlTest {

    private WebDriver driver;
    
    @BeforeMethod
    public void setUp() {
        System.setProperty(
	        "webdriver.chrome.driver", "путь/к/chromedriver");
        driver = new ChromeDriver();
    }
    
    @Test
    public void testButtonPresence() {
        // Замените путь на абсолютный путь к вашему example.html
        driver.get("file:///путь/к/example.html");
        
        // Поиск кнопки по её ID
        WebElement testButton = 
	        driver.findElement(By.id("testButton"));
	        
        // Проверка, что кнопка отображается
        Assert.assertTrue(
	        testButton.isDisplayed(), 
	        "Тестовая кнопка должна отображаться");
    }
    @AfterMethod
    public void tearDown() {
        driver.quit();
    }
}
```

**Разбор кода:**
- **Настройка WebDriver:** Устанавливается системное свойство для ChromeDriver и инициализируется драйвер. Это открывает окно браузера Chrome.
    
- **`@BeforeMethod` — `setUp`:** Этот метод подготавливает среду тестирования перед каждым тестовым методом, инициализируя WebDriver.
    
- **`@Test` — `testButtonPresence`:** Тестовый метод загружает локальный HTML-файл в браузере с помощью `driver.get()`. Находит элемент кнопки с помощью `driver.findElement(By.id("testButton"))`. Использует утверждение `Assert.assertTrue` для проверки отображения кнопки.
    
- **`@AfterMethod` — `tearDown`:** Этот метод выполняется после каждого тестового метода и отвечает за закрытие окна браузера и завершение сессии WebDriver.

Запустите тест, выполнив его как тест TestNG из IDE. Он откроет указанный HTML-файл в Chrome, проверит наличие кнопки и закроет браузер.

Этот пример демонстрирует базовый вариант использования комбинации TestNG с Selenium WebDriver для выполнения автоматизированного тестирования на простой HTML-странице. Такие тесты критически важны для проверки UI-элементов и их взаимодействий, что является неотъемлемой частью тестирования веб-приложений. Вы можете расширять эти основы для тестирования более сложных сценариев по мере прогресса в области автоматизации.

# Утверждения TestNG (TestNG Assertions)

TestNG предоставляет **набор методов утверждений** в классе `Assert`, которые критически важны для проверки правильности условий тестирования. 

Эти утверждения **являются ключевыми для проверки ожидаемых и фактических результатов в тестах** TestNG. Рассмотрим некоторые часто используемые утверждения: `assertEquals`, `assertTrue`, `assertFalse`, `assertNull` и `assertNotNull`.

---
## `assertEquals`

Проверяет **равенство двух значений или объектов**.
```java
@Test
public void testEquality() {
    String expected = "TestNG";
    String actual = "Test" + "NG";
    
    Assert.assertEquals(actual, expected, "Строки не равны");
}
```

Здесь `assertEquals` сравнивает две строки: `expected` и `actual`. 
> *Тест падает, если они не равны, и отображается указанное сообщение* ("Строки не равны").

---
## `assertTrue`

**Проверяет, что условие истинно.**

```java
@Test
public void testCondition() {
    boolean condition = 5 > 3;
    
    Assert.assertTrue(condition, "Условие не истинно");
}
```

`assertTrue` проверяет, является ли условие (`5 > 3`) истинным. Если нет, тест падает с сообщением "Условие не истинно".

---
## `assertFalse`

**Проверяет, что условие ложно.**

```java
@Test
public void testFalseCondition() {
    boolean condition = 3 > 5;
    Assert.assertFalse(condition, "Условие не ложно");
}
```

`assertFalse` проверяет, что условие (`3 > 5`) ложно. Если условие истинно, тест падает с сообщением "Условие не ложно".

---
## `assertNull`

Проверяет, что объект равен `null`.

```java
@Test
public void testNull() {
    Object myObject = null;
    Assert.assertNull(myObject, "Объект не null");
}
```

Этот метод проверяет, что `myObject` равен `null`. Если `myObject` не `null`, тест падает с сообщением "Объект не null".

---
## `assertNotNull`

Проверяет, что объект не равен `null`.

```java
@Test
public void testNotNull() {
    Object myObject = new Object();
    Assert.assertNotNull(myObject, "Объект null");
}
```

Это утверждение проверяет, что `myObject` не равен `null`. Если `myObject` равен `null`, тест падает с сообщением "Объект null".

# Параметризованное тестирование в TestNG

Параметризованное тестирование — это мощная техника в TestNG, которая позволяет выполнять **один и тот же тест несколько раз С РАЗНЫМИ НАБОРАМИ ВХОДНЫХ ДАННЫХ.** 

Этот подход чрезвычайно полезен, когда вам нужно протестировать функцию или фрагмент кода с различными входными данными, обеспечивая полное покрытие и проверку различных сценариев без написания множества тестовых методов для каждого набора данных.

В TestNG параметризованные тесты реализуются с использованием аннотации `@DataProvider`, которая предоставляет данные для теста, и аннотации `@Test`, которая потребляет данные для выполнения.

---
## Реализация параметризованного тестирования в TestNG

### **Шаг 1: Определение DataProvider**
Сначала определите метод с аннотацией `@DataProvider`, который возвращает двумерный массив объектов. Каждая строка в этом массиве представляет набор параметров; каждый столбец — значение параметра.

```java
import org.testng.annotations.DataProvider;

public class TestParameters {

    @DataProvider(name = "loginData")
    public Object[][] provideLoginData() {
        return new Object[][] {
            { "user1@example.com", "password1" },
            { "user2@example.com", "password2" },
            { "user3@example.com", "password3" }
        };
    }
}
```

В этом примере метод `provideLoginData` генерирует данные для гипотетического теста входа, где каждая строка представляет разные учетные данные пользователя.

### **Шаг 2: Создание тестового метода с использованием DataProvider**
Напишем тестовый метод, который использует данные, предоставленные DataProvider.

```java
import org.testng.Assert;
import org.testng.annotations.Test;

public class TestParameters {

    // Метод DataProvider из примера выше
    @Test(dataProvider = "loginData")
    public void testLogin(String email, String password) {
        System.out.println(
	        "Попытка входа с: " + email + " / " + password);
	        
        // Представьте функцию, которая пытается войти и возвращает boolean
        boolean result = attemptLogin(email, password);
        Assert.assertTrue(result, "Вход должен быть успешным");
    }
    
    private boolean attemptLogin(String email, String password) {
        // Фиктивная логика входа для иллюстрации
        return email.contains("@example.com") 
	        && password.startsWith("password");
    }
}
```

- DataProvider (`provideLoginData`) генерирует набор учетных данных.
    
- Аннотация `@DataProvider` называет этот набор данных `loginData`.
    
- Тестовый метод (`testLogin`) получает параметры (`email` и `password`) от DataProvider.
    
- Аннотация `@Test` связывается с DataProvider через атрибут `dataProvider`.
    
- Метод содержит фиктивную функцию входа и утверждение для проверки успешного входа.
    

> **Примечание:** Аннотация `@DataProvider` в TestNG и атрибут `dataProvider`, используемый в аннотации `@Test`, являются двумя частями одной функции, но служат разным ролям в параметризованном тестировании.

Когда этот тест запускается, TestNG вызывает `testLogin` три раза — по одному для каждого набора учетных данных, предоставленных методом `provideLoginData`. Это демонстрирует, как параметризованные тесты могут эффективно тестировать множество наборов данных с одним фрагментом тестового кода.

# Расширенная КОНФИГУРАЦИЯ TestNG и параллельное выполнение

По мере роста сложности и размера тестов TestNG в IT-проектах, эффективное управление и более быстрое выполнение тестов становятся первостепенными. 

Файл конфигурации `testng.xml` и параллельное выполнение тестов — это мощные функции TestNG, которые решают эти задачи. 

Этот раздел посвящен тому, как использовать `testng.xml` для настраиваемого выполнения тестов и включения параллельного тестирования, повышая управляемость и эффективность тестовых наборов.

---
## Использование testng.xml для выполнения тестов

Файл `testng.xml` **позволяет определять и группировать тестовые случаи,** ***управлять порядком выполнения тестов и указывать параметры.*** 

Ниже приведен базовый пример файла `testng.xml`, который определяет тестовый набор с двумя тестовыми группами.

```xml
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd">
<suite name="MyTestSuite">
    <test name="RegressionTests">
        <classes>
            <class name="com.example.tests.RegressionTest"/>
        </classes>
    </test>
    
    <test name="SmokeTests">
        <classes>
            <class name="com.example.tests.SmokeTest"/>
        </classes>
    </test>
</suite>
```

Эта конфигурация позволяет раздельно выполнять регрессионные и дымовые тесты, облегчая целенаправленные стратегии тестирования.

---
## Включение параллельного выполнения в testng.xml

Параллельное выполнение может значительно сократить общее время выполнения тестов. 

В файле `testng.xml` **атрибут** `parallel` **и** `thread-count` **позволяют запускать тесты, классы или методы параллельно** в зависимости от требований вашего проекта. 

Ниже приведен пример включения параллельного выполнения на уровне методов.

```xml
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd">
<suite name="MyParallelTestSuite" parallel="methods" thread-count="5">
    <test name="ParallelMethodTests">
        <classes>
            <class name="com.example.tests.ParallelMethodTest"/>
        </classes>
    </test>
</suite>
```

Эта конфигурация запускает до пяти методов параллельно, оптимизируя время выполнения для больших тестовых наборов.

---
## Реализация параллельного выполнения: практический пример

Рассмотрим сценарий, где несколько тестовых методов должны выполняться параллельно внутри одного класса. Следующий пример класса может выполняться параллельно в соответствии с конфигурацией в `testng.xml`.

```java
package com.example.tests;
import org.testng.annotations.Test;

public class ParallelMethodTest {
    @Test
    public void testMethodOne() throws InterruptedException {
        Thread.sleep(2000); // Только для демонстрации
        System.out.println("Test Method One.");
    }
    
    @Test
    public void testMethodTwo() throws InterruptedException {
        Thread.sleep(2000); // Только для демонстрации
        System.out.println("Test Method Two.");
    }
    // Дополнительные тестовые методы следуют
}
```

При выполнении в рамках параллельной конфигурации в `testng.xml` эти методы выполняются одновременно (при условии, что позволяют системные ресурсы), сокращая общее время выполнения.

# Лучшие практики использования TestNG с Selenium

Сочетание TestNG с Selenium образует мощный дуэт для автоматизированного тестирования. Для максимизации их эффективности важно придерживаться определенных лучших практик. 

Эти практики оптимизируют ваш процесс тестирования и обеспечивают поддерживаемость, масштабируемость и надежность тестовых наборов.

1. **Организуйте тесты с использованием аннотаций TestNG.** Используйте аннотации TestNG, такие как `@BeforeSuite`, `@BeforeTest`, `@BeforeClass`, `@BeforeMethod` и соответствующие `@After` аннотации для настройки и очистки тестовых сред. 
   Это ***гарантирует, что каждый тест выполняется в чистом состоянии.***
    
2. **Используйте тестирование на основе данных.** Используйте `@DataProvider` TestNG для тестирования на основе данных. Этот подход позволяет запускать один и тот же тест с разными наборами данных, повышая покрытие и эффективность тестирования.
    
3. **Приоритизируйте тестовые методы.** Используйте атрибут `priority` в аннотации `@Test` для упорядочивания тестовых методов. Это особенно полезно, когда некоторые тесты должны выполняться перед другими.
    
4. **Группируйте ваши тесты.** Используйте атрибут `groups` в TestNG для категоризации тестов (например, smoke, regression, sanity). Это позволяет запускать выбранные группы тестов независимо и управлять ими более эффективно.
    
5. **Поддерживайте независимость тестов.** Проектируйте тесты так, чтобы они были независимы друг от друга. Каждый тест должен выполняться самостоятельно, без зависимости от результатов других тестов (если это не требуется специально).
    
6. **Используйте утверждения эффективно.** Используйте методы утверждений TestNG или Selenium для проверки результатов тестов. Четкие и точные утверждения являются ключевыми для определения успеха или неудачи теста.
    
7. **Внедряйте параллельное выполнение.** Используйте функцию параллельного выполнения TestNG для одновременного запуска нескольких тестов, сокращая общее время выполнения.
    
8. **Обрабатывайте зависимости осторожно.** При использовании функций `dependsOnMethods` или `dependsOnGroups` убедитесь, что зависимости необходимы. Избыточная зависимость между тестами может привести к проблемам поддержки.
    
9. **Храните тесты и данные отдельно.** Храните тестовые данные (URL, учетные данные и т.д.) отдельно от тестовых скриптов, в идеале во внешних файлах или в DataProvider. Это облегчает управление данными и обновление тестов.
    
10. **Внедряйте непрерывную интеграцию.** Интегрируйте ваши тесты TestNG и Selenium в CI/CD-пайплайн для непрерывного тестирования и обратной связи.
    
11. **Регулярно пересматривайте и рефакторите.** Регулярно пересматривайте тестовый код на предмет улучшений и рефакторинга для повышения читаемости, производительности и поддерживаемости.
    
12. **Документируйте ваши тесты.** Поддерживайте четкую документацию для ваших тестовых случаев и кода — это особенно полезно для новых членов команды или при возвращении к тестам после длительного перерыва.
