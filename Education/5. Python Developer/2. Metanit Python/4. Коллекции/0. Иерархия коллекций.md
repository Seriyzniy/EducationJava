**Все встроенные коллекции (list, tuple, dict, set, str, range и т.д.) являются итерируемыми объектами** и наследуются (или, ==точнее, реализуют протокол==) от `Iterable` в иерархии абстрактных базовых классов (ABC) из модуля `collections.abc`.

## Иерархия коллекций в Python
В Python коллекции организованы в виде строгой иерархии абстрактных базовых классов (ABC) в модуле `collections.abc`.

Вот как выглядят основные ветки наследования:
```python
#Корневой интерфейс для всех, что можно перебирать
Iterable (collections.abc.Iterable)  
	│           
    │   # Добавляет метод __next__()
    ├── Iterator (collections.abc.Iterator) 
    │       │
    │       └── ... (генераторы, итераторы)
    │
    │   # Объединяет Iterable, Sized, Container
    ├── Collection (collections.abc.Collection)  
    │       │
	│       │   # Упорядоченные коллекции(list,tuple, str, range)
    │       ├── Sequence (collections.abc.Sequence)   
    │       │       ├── list
    │       │       ├── tuple
    │       │       ├── str
    │       │       └── range
    │       │   # Изменяемые последовательности (list)
    │       ├── MutableSequence  
    │       │       └── list
    │       │
    │       │   # Неизменяемые множества (frozenset)
    │       ├── Set (collections.abc.Set)   
    │       │       ├── frozenset
    │       │       └── MutableSet
    │       │           └── set
    │       │   # Коллекции "ключ-значение" (dict)
    │       └── Mapping (collections.abc.Mapping)  
    │               ├── dict
    │               └── MutableMapping
    │                   └── dict
    │
    └── (другие итерабельные объекты, не являющиеся коллекциями)
            └── (файлы, генераторы и т.д.)
```

## Что значит "наследуются от Iterable"?

В Python **нет классического наследования от класса `Iterable`** в том смысле, как в Java (через `extends`). Вместо этого используется **утиная типизация** и **абстрактные базовые классы** (ABC).

### 1. Протокол итерации (duck typing)
Любой объект считается **итерируемым**, если он реализует метод `__iter__()`, который возвращает итератор. 

Либо если он реализует `__getitem__()` с последовательными индексами (это более старый механизм, но тоже работает).
```python
# Все коллекции имеют метод __iter__
print(hasattr([1, 2, 3], "__iter__"))  # True
print(hasattr((1, 2), "__iter__"))     # True
print(hasattr({"a": 1}, "__iter__"))   # True
print(hasattr("hello", "__iter__"))    # True
print(hasattr(range(5), "__iter__"))   # True
```

### 2. Абстрактные базовые классы (ABC)
В модуле `collections.abc` есть абстрактный класс `Iterable`, который определяет метод `__iter__()`:

python
from collections.abc import Iterable
```python
# Все встроенные коллекции являются экземплярами Iterable
print(isinstance([1, 2, 3], Iterable))  # True
print(isinstance((1, 2), Iterable))     # True
print(isinstance({"a": 1}, Iterable))   # True
print(isinstance("hello", Iterable))    # True
print(isinstance(range(5), Iterable))   # True

# Но они НЕ являются подклассами Iterable в смысле issubclass?
# Они зарегистрированы через virtual subclassing
print(issubclass(list, Iterable))   # True
print(issubclass(dict, Iterable))   # True
```

Однако, если посмотреть на иерархию через `__mro__`:
```python
print(list.__mro__)
# (<class 'list'>, <class 'object'>)  # Нет Iterable!
print(tuple.__mro__)
# (<class 'tuple'>, <class 'object'>) # Нет Iterable!
```

**Почему так?** Потому что `isinstance()` и `issubclass()` работают с ABC через **регистрацию** (virtual subclassing), а не через реальное наследование. Классы регистрируются как "виртуальные подклассы" абстрактного класса, но не наследуют от него в классическом смысле.

## Проверка в коде
```python
from collections.abc import Iterable, Sequence, MutableSequence, Set, Mapping

# Все коллекции — итерабельные
print(isinstance([1, 2, 3], Iterable))  # True
print(isinstance((1, 2), Iterable))     # True
print(isinstance({"a": 1}, Iterable))   # True
print(isinstance({1, 2}, Iterable))     # True
print(isinstance("hello", Iterable))    # True
print(isinstance(range(5), Iterable))   # True


# Проверка на Sequence (упорядоченные коллекции)
print(isinstance([1, 2, 3], Sequence))   # True
print(isinstance((1, 2), Sequence))      # True
print(isinstance("hello", Sequence))     # True
print(isinstance(range(5), Sequence))    # True
print(isinstance({"a": 1}, Sequence))    # False (словарь — Mapping)


# Проверка на Mapping (ключ-значение)
print(isinstance({"a": 1}, Mapping))     # True
print(isinstance([1, 2, 3], Mapping))    # False


# Проверка на Set
print(isinstance({1, 2}, Set))           # True
print(isinstance([1, 2, 3], Set))        # False
```

## Важные концепции

|Концепция|Описание|
|---|---|
|**Iterable**|Объект, который можно перебирать (реализует `__iter__` или `__getitem__`)|
|**Iterator**|Объект, который возвращает следующий элемент (реализует `__next__`)|
|**Collection**|Объединяет `Iterable`, `Sized` (len) и `Container` (in)|
|**Sequence**|Упорядоченная коллекция с поддержкой индексов (list, tuple, str, range)|
|**MutableSequence**|Изменяемая последовательность (list)|
|**Mapping**|Коллекция "ключ-значение" (dict)|
|**Set**|Множество уникальных элементов (set, frozenset)|
