**Chain (цепочка)** — это последовательность компонентов LangChain, где выход одного компонента становится входом следующего.

Например, типичное LLM-приложение состоит из нескольких этапов:
```
Входные данные пользователя

        |
        v

Prompt Template
(создание правильного запроса)

        |
        v

LLM
(генерация ответа)

        |
        v

Output Parser
(преобразование результата)

        |
        v

Результат приложения
```

Каждый компонент в этой цепочке является `Runnable`.

То есть:
```
PromptTemplate
       |
       | Runnable
       |
       v

ChatOpenAI
       |
       | Runnable
       |
       v

OutputParser
       |
       | Runnable
       |
       v
```

Именно поэтому LangChain позволяет писать:
```python
chain = prompt | model | parser
```

---
# 1.2. Что такое LCEL

**LCEL (LangChain Expression Language)** — это декларативный способ создания цепочек из Runnable-компонентов.

Главная идея:

Вместо того чтобы вручную писать:
```python
prompt_result = prompt.invoke(data)

model_result = model.invoke(prompt_result)

final_result = parser.invoke(model_result)
```

можно описать поток данных:
```python
chain = prompt | model | parser
```

А затем вызвать:
```python
chain.invoke(data)
```

LangChain сам выполнит все этапы.

---
## 1.3. Императивный подход без LCEL

Рассмотрим простой пример.

Нужно сделать AI-помощника по Java.

Без LCEL:
```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_messages(
	[
	    (
	        "system",
	        "Ты эксперт по Java"
	    ),
	    (
	        "human",
	        "{question}"
	    )
	]
)

model = ChatOpenAI(
    model="gpt-4.1"
)


def ask_java_expert(question):

    prompt_message = prompt.invoke(
        {
            "question": question
        }
    )

    response = model.invoke(
        prompt_message
    )

    return response
```

Использование:
```python
answer = ask_java_expert(
    "Что такое JVM?"
)
```

Работает, но проблема:
- много промежуточного кода;
- сложно добавлять новые этапы;
- нет автоматического streaming;
- нет автоматической async-поддержки.

---
# 1.4. Декларативный подход через LCEL

Теперь тот же пример:
```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_messages(
	[
	    (
	        "system",
	        "Ты эксперт по Java"
	    ),
	    (
	        "human",
	        "{question}"
	    )
	]
)

model = ChatOpenAI(
    model="gpt-4.1"
)

chain = prompt | model
```

Теперь:
```python
response = chain.invoke(
	{
	    "question": "Что такое JVM?"
	}
)

print(response.content)
```

Что произошло:
```
{
 question:
 "Что такое JVM?"
}
        |
        v

ChatPromptTemplate

        |
        v

[
 SystemMessage,
 HumanMessage
]

        |
        v

ChatOpenAI

        |
        v

AIMessage
```

# 1.5. Оператор | - выход одного на вход другого

Оператор:
```python
|
```

означает:
> **Передай результат предыдущего Runnable в следующий Runnable**.

Например:
```
chain = A | B | C
```

равно:
```
Input

 |
 v

A.invoke()

 |
 v

B.invoke()

 |
 v

C.invoke()

 |
 v

Output
```

---

Пример:
```
chain = prompt | model
```

означает:
```
dict

 |
 v

PromptTemplate.invoke()

 |
 v

ChatOpenAI.invoke()

 |
 v

AIMessage
```

# 1.6. RunnableSequence

Когда пишется:
```
chain = prompt | model | parser
```

LangChain внутри создаёт:
```python
RunnableSequence(
    [
        prompt,
        model,
        parser
    ]
)
```

То есть:
```
RunnableSequence
       |
       |
       +---- PromptTemplate

       |
       +---- ChatOpenAI

       |
       +---- OutputParser
```

# 1.7. Основные методы Chain

Так как Chain является Runnable, у него есть те же методы:

## invoke()
**Один запрос**:
```python
response = chain.invoke(
	{
	    "question": "Что такое Kafka?"
	}
)
```

---
## batch()
**Несколько независимых запросов**:
```python
responses = chain.batch(
	[
	    {
	        "question": "Что такое Kafka?"
	    },
	
	    {
	        "question": "Что такое Redis?"
	    }
	]
)
```

Результат:
```python
[
    response_about_kafka,
    response_about_redis
]
```

---
## stream()
Потоковый вывод:
```python
for chunk in chain.stream(
	{
	    "question": "Объясни Spring Boot"
	}
):
    print(chunk.content)
```

Получаем:
```python
Spring
Boot
is
a
framework...
```

# 1.8. RunnableParallel

Иногда нужно выполнить несколько цепочек параллельно.

Например:

Для статьи нужно получить:
- краткое описание;
- список ключевых слов.

Вместо:
```
Вход

 |
 +------------+
 |            |
 v            v

Summary     Keywords
```

можно использовать:
```python
from langchain_core.runnables import RunnableParallel


chain = RunnableParallel(
	{
	    "summary": summary_chain, # Передается цепочка LCEL, которая содержит промпт и модель для сокращения текста
	    "keywords": keywords_chain # Передается цепочка LCEL, которая содержит промпт и модель для получения ключевых слов
	}
)
```

Теперь:
```python
result = chain.invoke(
	{
	    "text": "Большой текст статьи..."
	}
)
```

Получаем:
```json
{
    "summary": "Краткое содержание...",
    "keywords": [
        "Java",
        "Spring",
        "Kafka"
    ]
}
```
