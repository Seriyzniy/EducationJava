## Интерфейс Runnable
`Runnable` — это **базовый интерфейс (точнее, базовый абстрактный класс) LangChain Core**, который задаёт единый способ работы с компонентами.

В Python это примерно:
```python
class Runnable:
    
    def invoke(self, input):
        pass

    def batch(self, inputs):
        pass

    def stream(self, input):
        pass
```

То есть идея:
> Любой объект, который умеет принять вход и выдать выход, может быть Runnable.

### Все ли модели наследуются от Runnable?
Да, концептуально.

Например, в LangChain есть:
```
Runnable
    |
    +-- BaseLanguageModel
            |
            +-- BaseChatModel
                    |
                    +-- ChatOpenAI
                    +-- ChatAnthropic
                    +-- ChatGoogleGenerativeAI
```

То есть:
```
Runnable
    |
    |
    +----------------+
    |                |
 ChatOpenAI     PromptTemplate
    |
    |
 OutputParser
```

Все эти объекты имеют одинаковый контракт.

---
Например:
```
model = ChatOpenAI()
```

На самом деле:
```
ChatOpenAI

является

BaseChatModel

является

Runnable
```

Поэтому работает:
```
model.invoke(...)
```

## 1. Создание LLM модели

### 1.1. Базовый пример
```python
from langchain_openai import ChatOpenAI
model = ChatOpenAI(
    model="gpt-4.1",
    temperature=0.2
)
```

---
### 1.2. Основные параметры

#### **Параметр `model`**

Определяет, какая модель OpenAI будет использоваться:
```python
model="gpt-4.1"
```

Разные модели имеют различные характеристики:
- **Качество** — точность и глубина ответов;
    
- **Скорость** — время генерации;
    
- **Стоимость** — цена за токен.

---
#### **Параметр `temperature`**

Управляет степенью случайности в ответах модели.

**Низкое значение** (`temperature=0.1`):
- Ответы **стабильные** и **предсказуемые**;
    
- Подходит для:
    - анализа данных;
        
    - генерации JSON;
        
    - работы с бизнес-логикой.
        

**Высокое значение** (`temperature=0.9`):
- Ответы **более креативные** и разнообразные;
    
- Подходит для:
    - генерации идей;
        
    - написания текстов;
        
    - творческих задач.

## 2. Метод `invoke()`

### 2.1. Назначение
`invoke()` — основной способ вызова **Runnable**. Принимает **один вход** и возвращает **один результат**.

**Схема работы:**
```text
Один input
    |
    v
 Runnable
    |
    v
Один output
```

### 2.2. Пример использования

**Простой вызов:**
```python
response = model.invoke("Explain what Java is")
print(response)
# AIMessage(content="Java is a programming language...")
```

**Правильный способ для Chat Model — передача сообщений:**

```python
from langchain_core.messages import HumanMessage

response = model.invoke([
    HumanMessage("What is Spring Boot?")
])
# AIMessage(content="Spring Boot is a framework...")
```

### 2.3. Что происходит внутри
При вызове `model.invoke(messages)` LangChain:
1. Преобразует Python-объекты в формат API провайдера:
```json
{
  "role": "user",
  "content": "Question"
}
```

2. Отправляет запрос к LLM;
    
3. Возвращает ответ в виде `AIMessage`.

## 3. Метод `batch()`

### 3.1. Назначение

`batch()` используется для **параллельной обработки множества независимых запросов**.

**Схема работы:**
```text
Input 1 ----\
Input 2 -----\
Input 3 ------> Runnable
Input 4 -----/
              |
              v
         Output 1
         Output 2
         Output 3
         Output 4
```

### 3.2. Пример использования
```python
questions = [
    "What is Java?",
    "What is Python?",
    "What is Go?"
]

responses = model.batch(questions)
# Результат:
# [
#   AIMessage("Java is..."),
#   AIMessage("Python is..."),
#   AIMessage("Go is...")
# ]
```

### 3.3. Важное уточнение

`batch()` **НЕ объединяет** запросы в один промпт.

**Это не:**
```text
User: 
Explain Java. 
Explain Python. 
Explain Go.
```

**А это:**
```text
Request 1: Explain Java.
Request 2: Explain Python.  
Request 3: Explain Go.
```

Просто LangChain оптимизирует выполнение, отправляя запросы параллельно.

### 3.4. Где используется `batch()`

**1. Анализ большого количества данных**
```python
reviews = [
    "Great product",
    "Bad service",
    "Very fast delivery"
]

# Определение настроения каждого отзыва
model.batch(reviews)
```

**2. Обработка документов**
- Вместо цикла:
```python
for document in documents:
    model.invoke(document)
```

- Используют:
```python
model.batch(documents)  # 1000 документов → краткие описания
```

## 4. Метод `stream()`

### 4.1. Назначение

`stream()` возвращает результат **по частям** (чанками) по мере генерации текста моделью.

**Обычный вызов** — ожидание полного ответа:
```python
response = model.invoke("Explain Kubernetes")
# Ждем: ....................
# Получаем полный ответ
```

**Стриминг** — получение по частям:
```python
for chunk in model.stream("Explain Kubernetes"):
    print(chunk.content, end="")
# Вывод: Kubernetes is a container orchestration system
```

### 4.2. Что возвращает `stream()`

Каждый чанк — это не полный `AIMessage`, а его часть:
```python
AIMessageChunk(content="Kubernetes")
AIMessageChunk(content=" is")
AIMessageChunk(content=" a")
# и т.д.
```

### 4.3. Где используется
- **Чат-интерфейсы** — пользователь видит текст по мере печатания;
    
- **Голосовые ассистенты** — пошаговое озвучивание;
    
- **Длинные ответы** — улучшение пользовательского опыта.
    

Например, в ChatGPT текст появляется сразу благодаря streaming.

## 5. Асинхронные методы

Для каждого синхронного метода существуют асинхронные версии:

|Синхронный|Асинхронный|
|---|---|
|`invoke()`|`ainvoke()`|
|`batch()`|`abatch()`|
|`stream()`|`astream()`|

### 5.1. Пример использования
```python
response = await model.ainvoke("Explain Kafka")
```

### 5.2. Где применяются
Асинхронные версии используются в:
- **FastAPI** и других веб-фреймворках;
    
- **Высоконагруженных сервисах**;
    
- **Async-бэкендах**, где важна производительность.
