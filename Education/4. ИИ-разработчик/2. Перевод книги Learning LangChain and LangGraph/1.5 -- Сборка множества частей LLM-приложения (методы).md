Ключевые компоненты, которые вы изучили до сих пор, являются essential строительными блоками фреймворка LangChain. Что подводит нас к критическому вопросу: как эффективно комбинировать их для создания вашего LLM-приложения?

### Использование интерфейса Runnable
Как вы могли заметить, все примеры кода, использованные до сих пор, применяют схожий интерфейс и метод `invoke()` для генерации выводов от модели (или шаблона запроса, или парсера вывода). 

Все компоненты имеют следующее:
- Существует общий интерфейс с этими методами:
    - `invoke`: преобразует один вход в один выход
        
    - `batch`: эффективно преобразует множество входов в множество выходов
	      Например, вместо трёх отдельных вызовов `invoke()` можно сделать один `batch([request1, request2, request3])`. Он работает не только с LLM, но и с целыми цепочками (`prompt | model | parser`).
			Важно: `batch()` **не гарантирует один HTTP-запрос к API модели**. Обычно **LangChain просто выполняет НЕСКОЛЬКО ВЫЗОВОВ ПАРАЛЛЕЛЬНО**, чтобы ускорить обработку. Настоящий HTTP Batch API зависит от конкретного провайдера LLM. Используется для массовой обработки: документов, сообщений, товаров и других независимых задач.
        
    - `stream`: транслирует вывод из одного входа по мере его генерации
        
- Существуют встроенные утилиты для повторных попыток, запасных вариантов, схем и конфигурируемости во время выполнения.
    
- В Python каждый из трех методов имеет асинхронные эквиваленты.

Таким образом, все компоненты ведут себя одинаково, и интерфейс, изученный для одного из них, применим ко всем:

**Python**
```python
from langchain_openai.llms import ChatOpenAI

model = ChatOpenAI()
completion = model.invoke('Hi there!')  # 'Hi!'

completions = model.batch(['Hi there!', 'Bye!'])  
# ['Hi!', 'See you!']

for token in model.stream('Bye!'):
    print(token)
# Good
# bye
# !
```

В этом примере вы видите, как работают три основных метода:
- `invoke()` принимает один вход и возвращает один выход.
    
- `batch()` принимает список входов и возвращает список выходов.
    
- `stream()` принимает один вход и возвращает итератор частей вывода по мере их поступления.

В некоторых случаях, когда базовый компонент не поддерживает итеративный вывод, будет одна часть, содержащая весь вывод.

Вы можете комбинировать эти компоненты двумя способами:
- **Императивный**  
Вызов ваших компонентов напрямую, например, с помощью `model.invoke(...)`

- **Декларативный**  
Использование LangChain Expression Language (LCEL), как описано в следующем разделе


**Таблица 1-1** суммирует их различия, и мы увидим каждый из них в действии далее.

**Таблица 1-1. Основные различия между императивной и декларативной композицией.**

|                                   | Императивный                                                 | Декларативный  |
| --------------------------------- | ------------------------------------------------------------ | -------------- |
| Синтаксис                         | Весь Python или JavaScript                                   | LCEL           |
| Параллельное выполнение           | Python: с потоками или корутинами; JavaScript: с Promise.all | Автоматическое |
| Автоматическая потоковая передача | С ключевым словом yield                                      | Автоматическая |
| Асинхронное выполнение            | С асинхронными функциями                                     | Автоматическое |

### Императивная композиция

Императивная композиция — это просто красивое название для написания кода, к которому вы привыкли, компонуя эти компоненты в функции и классы. Вот пример, объединяющий запросы, модели и парсеры вывода:

**Python**
```python
from langchain_openai.chat_models import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import chain

# строительные блоки
template = ChatPromptTemplate.from_messages([
    ('system', 'You are a helpful assistant.'),
    ('human', '{question}'),
])

model = ChatOpenAI()

# объединяем их в функцию
# декоратор @chain добавляет тот же интерфейс Runnable
@chain
def chatbot(values):
    prompt = template.invoke(values)
    return model.invoke(prompt)
    
# используем
chatbot.invoke({
    "question": "Which model providers offer LLMs?"
})
```

**Вывод:**
```text
AIMessage(content="Hugging Face's `transformers` library, OpenAI using the `openai` library, and Cohere using the `cohere` library offer LLMs.")
```

Предыдущее — это полный пример чат-бота, использующего запрос и чат-модель. Как видите, он использует знакомый синтаксис Python и поддерживает любую пользовательскую логику, которую вы захотите добавить в эту функцию.

---
С другой стороны, если вы хотите включить **поддержку потоковой передачи или асинхронности**, вам придется изменить вашу функцию для их поддержки. 

***Например, поддержка потоковой передачи*** может быть добавлена следующим образом:

**Python**
```python
@chain
def chatbot(values):
    prompt = template.invoke(values)
    for token in model.stream(prompt):
        yield token
        
for part in chatbot.stream({
    "question": "Which model providers offer LLMs?"
}):
    print(part)
```

**Вывод:**
```text
AIMessageChunk(content="Hugging")
AIMessageChunk(content=" Face's")
AIMessageChunk(content=" `transformers`")
...
```

Итак, в Python вы можете включить потоковую передачу для вашей пользовательской функции, возвращая значения, которые вы хотите транслировать, а затем вызывая ее с помощью `stream`.

---
Для **асинхронного выполнения** вы перепишете вашу функцию следующим образом:

**Python**
```python
@chain
async def chatbot(values):
    prompt = await template.ainvoke(values)
    return await model.ainvoke(prompt)
    
await chatbot.ainvoke({
    "question": "Which model providers offer LLMs?"
})
# > AIMessage(content="""Hugging Face's `transformers` library, OpenAI using the `openai` library, and Cohere using the `cohere` library offer LLMs.""")
```

Это относится только к Python, так как асинхронное выполнение является единственным вариантом в JavaScript.

---
### Декларативная композиция

LCEL — это декларативный язык для компоновки компонентов LangChain. 

**LangChain компилирует LCEL-композиции в оптимизированный план выполнения с автоматической параллелизацией, потоковой передачей, трассировкой и асинхронной поддержкой.**

Давайте посмотрим на тот же пример с использованием LCEL:

**Python**
```python
from langchain_openai.chat_models import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

# строительные блоки
template = ChatPromptTemplate.from_messages([
    ('system', 'You are a helpful assistant.'),
    ('human', '{question}'),
])
model = ChatOpenAI()

# объединяем с оператором |
chatbot = template | model

# используем
chatbot.invoke({
    "question": "Which model providers offer LLMs?"
})
```

**Вывод:**
```text
AIMessage(content="Hugging Face's `transformers` library, OpenAI using the `openai` library, and Cohere using the `cohere` library offer LLMs.")
```

Важно, что последняя строка одинакова в обоих примерах — то есть вы используете функцию и последовательность LCEL одинаково, с помощью `invoke/stream/batch`. И в этой версии вам не нужно ничего делать для использования потоковой передачи:

**Python**
```python
chatbot = template | model

for part in chatbot.stream({
    "question": "Which model providers offer LLMs?"
}):
    print(part)
# > AIMessageChunk(content="Hugging")
# > AIMessageChunk(content=" Face's")
# > AIMessageChunk(content=" `transformers`")
# ...
```

И, только для Python, то же самое для использования асинхронных методов:

**Python**
```python
chatbot = template | model
await chatbot.ainvoke({
    "question": "Which model providers offer LLMs?"
})
```

## Резюме

В этой главе вы узнали о строительных блоках и ключевых компонентах, необходимых для создания LLM-приложений с использованием LangChain. LLM-приложения по сути представляют собой цепочку, состоящую из большой языковой модели для создания предсказаний, инструкций запроса для направления модели к желаемому выводу и опционального парсера вывода для преобразования формата вывода модели.

Все компоненты LangChain имеют общий интерфейс с методами `invoke`, `stream` и `batch` для обработки различных входных и выходных данных. Их можно комбинировать и выполнять императивно, вызывая их напрямую, или декларативно, используя LCEL.

Императивный подход полезен, если вы намереваетесь написать много пользовательской логики, тогда как декларативный подход полезен для простой сборки существующих компонентов с ограниченной кастомизацией.
