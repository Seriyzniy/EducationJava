## Генерация текстовых встраиваний (ГЕНЕРАЦИЯ ЭБМЕНДИНГОВ)
LangChain также имеет класс `Embeddings`, р**азработанный для взаимодействия с моделями текстовых встраиваний** — включая OpenAI, Cohere и Hugging Face — и генерации векторных представлений текста. 

Этот ==класс предоставляет два метода==: 
- один для встраивания документов 
	- принимает список текстовых строк на вход
	
- один для встраивания запроса. 
	- принимает одну текстовую строку.

Вот пример встраивания документа с использованием модели встраиваний OpenAI:

**Python**
```python
from langchain_openai import OpenAIEmbeddings

model = OpenAIEmbeddings()
embeddings = model.embed_documents([
    "Hi there!",
    "Oh, hello!",
    "What's your name?",
    "My friends call me World",
    "Hello World!"
])
```

### ПРИМЕР ПОСТРОЕНИЯ ЭМБЕНДИНГОВ ДЛЯ ЧАНКОВ ТЕКСТА
Теперь давайте посмотрим сквозной пример с использованием трех возможностей, которые мы уже видели:
- Загрузчики документов для преобразования любого документа в обычный текст
    
- Разбиватели текста для разбиения каждого большого документа на много маленьких
    
- Модели встраиваний для создания числового представления смысла каждого фрагмента

## Хранение встраиваний в векторном хранилище

Ранее в этой главе мы обсуждали вычисление косинусного сходства для измерения сходства между векторами в векторном пространстве. 


> [!NOTE] Векторная БД
> Векторное хранилище — это база данных, предназначенная для хранения векторов и выполнения сложных вычислений, таких как косинусное сходство, эффективно и быстро.


В отличие от традиционных баз данных, специализирующихся на хранении структурированных данных (таких как JSON-документы или данные, соответствующие схеме реляционной базы данных), **векторные хранилища работают с неструктурированными данными, включая текст и изображения.** 
> Как и традиционные базы данных, *векторные хранилища способны выполнять операции создания, чтения, обновления, удаления (CRUD) и поиска*.

Векторные хранилища открывают широкий спектр случаев использования, включая масштабируемые приложения, которые используют ИИ для ответов на вопросы о больших документах, как показано на **Рисунке 2-4**.

![[Pasted image 20260712124244.png]]
**Рисунок 2-4. Загрузка, встраивание, хранение и извлечение релевантных документов из векторного хранилища**

**Рисунок 2-4** иллюстрирует, как встраивания документов вставляются в векторное хранилище и как позже, когда отправляется запрос, похожие встраивания извлекаются из векторного хранилища.

В настоящее время существует множество поставщиков векторных хранилищ на выбор, каждый из которых специализируется на различных возможностях. Ваш выбор должен зависеть от критических требований вашего приложения, включая мультитенантность, возможности фильтрации по метаданным, производительность, стоимость и масштабируемость.

Хотя векторные хранилища являются нишевыми базами данных, созданными для управления векторными данными, есть несколько недостатков при работе с ними:

- Большинство векторных хранилищ относительно новы и могут не выдержать испытания временем.
    
- Управление и оптимизация векторных хранилищ могут представлять собой довольно крутую кривую обучения.
	
- Управление отдельной базой данных добавляет сложности вашему приложению и может истощать ценные ресурсы.
    

К счастью, **возможности векторных хранилищ недавно были расширены для PostgreSQL** (популярной реляционной базы данных с открытым исходным кодом) через расширение pgvector. Это позволяет вам использовать ту же базу данных, с которой вы уже знакомы, и поддерживать как ваши транзакционные таблицы (например, таблицу пользователей), так и ваши таблицы для векторного поиска.

## Настройка PGVector

Чтобы использовать Postgres и PGVector, вам нужно выполнить несколько шагов настройки:

1. Убедитесь, что у вас установлен Docker на вашем компьютере, следуя инструкциям для вашей операционной системы.
    
2. Выполните следующую команду в вашем терминале; она запустит экземпляр Postgres на вашем компьютере, работающий на порту 6024:
    

```bash
docker run \
    --name pgvector-container \
    -e POSTGRES_USER=langchain \
    -e POSTGRES_PASSWORD=langchain \
    -e POSTGRES_DB=langchain \
    -p 6024:5432 \
    -d pgvector/pgvector:pg16
```

Откройте панель управления Docker и вы должны увидеть зеленый статус выполнения рядом с pgvector-container.

3. Сохраните строку подключения для использования в вашем коде; она понадобится нам позже:
```text
postgresql+psycopg://langchain:langchain@localhost:6024/langchain
```

## Работа с векторными хранилищами

Продолжая с того места, где мы остановились в предыдущем разделе о встраиваниях, давайте теперь посмотрим на пример загрузки, разбиения, встраивания и хранения документа в PGVector:

**Python**
```python
# сначала pip install langchain-postgres
from langchain_community.document_loaders import TextLoader
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_postgres.vectorstores import PGVector
from langchain_core.documents import Document
import uuid

# Загрузка документа, разбиение на фрагменты
raw_documents = TextLoader('./test.txt').load()
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)

documents = text_splitter.split_documents(raw_documents)

# Встраивание каждого фрагмента и вставка в векторное хранилище
embeddings_model = OpenAIEmbeddings()

connection = 'postgresql+psycopg://langchain:langchain@localhost:6024/langchain'

db = PGVector.from_documents(
    documents,
    embeddings_model,
    connection=connection,
)
```

Обратите внимание, как мы переиспользуем код из предыдущих разделов, чтобы 
- сначала загрузить документы с помощью загрузчика, 
- а затем разбить их на меньшие фрагменты. 
- Затем мы *создаем экземпляр модели встраиваний*, которую хотим использовать — *в данном случае OpenAI*. Обратите внимание, что вы можете использовать любую другую модель встраиваний, поддерживаемую LangChain.

Далее у нас **новая строка кода, которая создает векторное хранилище на основе документов**, модели встраиваний и строки подключения. Это сделает несколько вещей:

- *Установит соединение с экземпляром* Postgres, работающим на вашем компьютере (см. "Настройка PGVector").
    
- **Выполнит любую необходимую настройку, такую как создание таблиц для хранения ваших документов и векторов,** *если вы запускаете это в первый раз*.
    
- ==Создаст встраивания для каждого переданного документа,== используя выбранную вами модель.
    
- **Сохранит встраивания, метаданные документа и текстовое содержимое документа в Postgres**, готовые для поиска.

### ПОИСК 
Давайте посмотрим, как ==выглядит поиск документов:==
**Python**
```python
db.similarity_search("query", k=4)
```

Этот метод найдет наиболее релевантные документы (которые вы ранее индексировали), следуя этому процессу:

- Поисковый запрос — в данном случае слово *"query"* — будет отправлен модели встраиваний для получения его встраивания.
    
- Затем он выполнит запрос к Postgres **для поиска N (в данном случае 4) ранее сохраненных встраиваний, которые наиболее похожи на ваш запрос.**
    
- Наконец, он извлечет текстовое содержимое и метаданные, связанные с каждым из этих встраиваний.

Модель теперь может вернуть список Document, отсортированных по тому, насколько они похожи на запрос — сначала самый похожий, затем второй по похожести, и так далее.

### ВСТАВКА ДОКУМЕНТОВ
Вы также можете добавлять больше документов в существующую базу данных. Давайте посмотрим на пример:

**Python**
```python

ids = [str(uuid.uuid4()), str(uuid.uuid4())]

db.add_documents(
    [
        Document(
            page_content="there are cats in the pond",
            metadata={"location": "pond", "topic": "animals"}
        ),
        Document(
            page_content="ducks are also found in the pond",
            metadata={"location": "pond", "topic": "animals"}
        ),
    ],
    ids=ids,
)
```

Метод add_documents, который мы здесь используем, будет следовать процессу, аналогичному from_documents:

- Создаст встраивания для каждого переданного документа, используя выбранную вами модель.
    
- Сохранит встраивания, метаданные документа и текстовое содержимое документа в Postgres, готовые для поиска.
    

В этом примере мы используем необязательный аргумент ids для присвоения идентификаторов каждому документу, что позволяет нам обновлять или удалять их позже.

### УДАЛЕНИЕ ДОКУМЕНТА
Вот пример операции удаления:

**Python**
```python
db.delete(ids=[ids[1]])
```

Это удаляет второй вставленный документ, используя его универсальный уникальный идентификатор (UUID). Теперь давайте посмотрим, как сделать это более систематическим образом.
