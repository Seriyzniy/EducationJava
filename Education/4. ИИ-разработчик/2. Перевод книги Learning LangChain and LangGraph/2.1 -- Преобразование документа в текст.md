## Преобразование ваших документов в текст

Как упоминалось в начале главы, **первый шаг в предварительной обработке вашего документа — это преобразование его в текст.** 

Для этого вам нужно создать логику для парсинга и извлечения документа с минимальной потерей качества. К счастью, ==LangChain предоставляет загрузчики документов== (document loaders), **которые обрабатывают логику парсинга и позволяют вам "загружать" данные из различных источников в класс Document**, состоящий из текста и связанных с ним метаданных.

Например, рассмотрим простой .txt файл. Вы можете просто импортировать класс `TextLoader` от LangChain для извлечения текста, как показано ниже:

**Python**
```python
from langchain_community.document_loaders import TextLoader

loader = TextLoader("./test.txt")
loader.load()
```

**Вывод:**
```text
[Document(page_content='text content \n', metadata={'source': './test.txt'})]
```

*Предыдущий блок кода предполагает, что у вас есть файл с именем test.txt в вашей текущей директории.* Использование всех загрузчиков документов LangChain следует схожему шаблону:

1. Начните с выбора загрузчика для вашего типа документа из длинного списка интеграций.
    
2. Создайте экземпляр соответствующего загрузчика вместе с любыми параметрами для его настройки, включая расположение ваших документов (обычно путь в файловой системе или веб-адрес).
    
3. Загрузите документы, вызвав `load()`, который возвращает список документов, готовых для передачи на следующий этап (подробнее об этом скоро).

Помимо .txt файлов, ==LangChain предоставляет загрузчики документов для других популярных типов файлов,== включая .csv, .json и Markdown, а также интеграции с популярными платформами, такими как Slack и Notion.

Например, вы можете использовать `WebBaseLoader` **для загрузки HTML с веб-URL и его парсинга в текст**.

Установите пакет **beautifulsoup4**:
```bash
pip install beautifulsoup4
```

**Python**
```python
from langchain_community.document_loaders import WebBaseLoader

loader = WebBaseLoader("https://www.langchain.com")
loader.load()
```

В случае нашего **использования PDF** от Tesla, мы можем использовать `PDFLoader` **от LangChain для извлечения текста из PDF-документа:**

**Python**
```python
# установка библиотеки для парсинга PDF
# pip install pypdf
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("./test.pdf")
pages = loader.load()
```

Текст был извлечен из PDF-документа и сохранен в классе Document. 

Но есть проблема. 

**Загруженный документ имеет длину более 100 000 символов, поэтому он не поместится в контекстное окно подавляющего большинства LLM** или моделей встраиваний. 

Чтобы преодолеть это ограничение, ==нам нужно разбить Document на управляемые фрагменты текста==, которые мы позже сможем преобразовать во встраивания и использовать для семантического поиска, что подводит нас ко второму шагу (извлечению).

> **СОВЕТ**  
> **LLM и модели** встраиваний **разработаны с жестким ограничением на размер входных и выходных токенов**, которые они могут обработать. 
> 
> Этот ==лимит обычно называется контекстным окном== (context window) и обычно применяется к комбинации входа и выхода; то есть, если контекстное окно равно 100 (мы поговорим о единицах через секунду), и ваш вход имеет размер 90, выход может быть не длиннее 10. 
> 
> Контекстные окна обычно измеряются в количестве токенов, например 8 192 токена. 
> 
> Токены, как упоминалось в Предисловии, являются представлением текста в виде чисел, причем каждый токен обычно охватывает от трех до четырех символов английского текста.
