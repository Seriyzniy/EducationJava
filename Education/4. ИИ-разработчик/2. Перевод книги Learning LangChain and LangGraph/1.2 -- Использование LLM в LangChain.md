Напомним, БЯМ являются движущим механизмом большинства приложений генеративного ИИ. 

LangChain предоставляет **два простых интерфейса для взаимодействия с любым поставщиком API LLM**
- Чат-модели (==Chat models==)
    
- БЯМ (==LLMs==)

Интерфейс БЯМ просто принимает строковый запрос на вход, отправляет ввод поставщику модели и затем возвращает предсказание модели в качестве вывода.

Давайте импортируем обертку OpenAI LLM от LangChain, чтобы вызвать предсказание модели с помощью простого запроса:

**Python**
```python
from langchain_openai.llms import OpenAI

model = OpenAI(model="gpt-3.5-turbo")

model.invoke("The sky is")
```

**Вывод:**
```text
'The sky is blue!'
```

> **СОВЕТ**  
> Обратите внимание на параметр `model`, переданный в `OpenAI`. Это наиболее распространенный параметр для настройки при использовании БЯМ или чат-модели — базовая модель для использования, поскольку большинство поставщиков предлагают несколько моделей с разными компромиссами по возможностям и стоимости (обычно более крупные модели более способны, но также дороже и медленнее). См. обзор моделей, предлагаемых OpenAI.
> 
> ==Другие полезные параметры== для настройки включают следующие, предлагаемые большинством поставщиков:
> 
> **temperature**  
> Этот параметр управляет алгоритмом семплирования, используемым для генерации вывода. Более низкие значения дают более предсказуемые результаты (например, 0.1), в то время как более высокие значения генерируют более креативные или неожиданные результаты (например, 0.9). 
> 
> Различные задачи будут требовать разных значений для этого параметра. Например, создание структурированного вывода обычно выигрывает от более низкой температуры, тогда как задачи творческого письма лучше работают с более высоким значением.
> 
> **max_tokens**  
> Этот параметр ограничивает размер (и стоимость) вывода. Более низкое значение может заставить БЯМ прекратить генерацию вывода до достижения естественного конца, поэтому вывод может выглядеть усеченным.
> 
> Помимо этих, каждый поставщик предоставляет различный набор параметров. Мы рекомендуем обратиться к документации того поставщика, которого вы выбрали. В качестве примера см. платформу OpenAI.

## Роли
В качестве альтернативы, интерфейс чат-модели обеспечивает диалог между пользователем и моделью. 

Причина, по которой это отдельный интерфейс, заключается в том, что популярные поставщики БЯМ, такие как OpenAI, различают сообщения, отправляемые модели и от модели, по ролям: пользователь, ассистент и система (здесь роль обозначает тип контента, который содержит сообщение):
- **Системная роль** — используется для инструкций, которые модель должна использовать для ответа на вопрос пользователя.
    
- **Роль пользователя** — используется для запроса пользователя и любого другого контента, созданного пользователем.
    
- **Роль ассистента** — используется для контента, сгенерированного моделью.
    

Интерфейс чат-модели упрощает настройку и управление диалогами в вашем ИИ-чат-приложении. Вот пример использования модели ChatOpenAI от LangChain:

**Python**
```python
from langchain_openai.chat_models import ChatOpenAI
from langchain_core.messages import HumanMessage

model = ChatOpenAI()

prompt = [HumanMessage("What is the capital of France?")]

model.invoke(prompt)
```

**Вывод:**
```text
AIMessage(content='The capital of France is Paris.')
```

## Типы сообщений
Вместо одной строки запроса чат-модели используют различные типы интерфейсов чат-сообщений, связанных с каждой из упомянутых ранее ролей. Они включают:

- **HumanMessage** — сообщение, отправленное с точки зрения человека, с ролью пользователя.
    
- **AIMessage** — сообщение, отправленное с точки зрения ИИ, с которым взаимодействует человек, с ролью ассистента.
    
- **SystemMessage** — сообщение, задающее инструкции, которым ИИ должен следовать, с системной ролью.
    
- **ChatMessage** — сообщение, позволяющее произвольно устанавливать роль.
    

Давайте включим инструкцию SystemMessage в наш пример:

**Python**
```python
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_openai.chat_models import ChatOpenAI

model = ChatOpenAI()

system_msg = SystemMessage(
    '''You are a helpful assistant that responds to questions with exclamation marks.'''
)

human_msg = HumanMessage('What is the capital of France?')

model.invoke([system_msg, human_msg])
```

**Вывод:**
```text
AIMessage(content='Paris!!!')
```

Как видите, модель подчинилась инструкции, предоставленной в SystemMessage, даже несмотря на то, что она отсутствовала в вопросе пользователя. Это позволяет вам предварительно настроить ваше ИИ-приложение для ответа относительно предсказуемым образом на основе ввода пользователя.

# НЕКОТОРЫЕ ПОЯСНЕНИЯ
# Роли в Chat Model
## Зачем нужны роли

В обычной LLM модель получает просто текст:

```
"Объясни, что такое Java"
```

У неё нет информации:

- кто написал этот текст;
- является ли это вопросом пользователя или инструкцией разработчика;
- является ли это предыдущим ответом модели.

Chat Model решает эту проблему через **роли сообщений**.

Роль — это метка, которая сообщает модели назначение сообщения:
```
Кто говорит → Роль → Назначение сообщения
```

Например:
```
System:
Ты эксперт по Java.

User:
Что такое HashMap?

Assistant:
HashMap — это структура данных...
```

Для модели это уже не просто три строки текста, а структурированный диалог.

---
## Основные роли

### System role (системная роль)

**System** — это сообщение с инструкциями для модели.

Оно задаёт:
- поведение модели;
- её роль;
- стиль ответа;
- ограничения;
- правила обработки запросов.

Пример:
```
System:
Ты — опытный Java-разработчик.
Отвечай подробно и приводи примеры кода.
```

После этого пользовательский запрос:
```
User:
Что такое Stream API?
```

будет обработан с учетом системной инструкции:
```
Assistant:
Stream API — это механизм Java...
```

---

Главная особенность System:

- обычно задаётся разработчиком приложения;
- находится в начале истории сообщений;
- применяется ко всему дальнейшему диалогу.

Например, в банковском приложении:
```
System:
Ты — банковский помощник.
Не запрашивай пароль пользователя.
Отвечай только по банковским продуктам.
```

Далее пользователь может спрашивать:
```
User:
Как открыть вклад?
```

Модель должна отвечать согласно правилам System.

---
### User role (роль пользователя)

**User** — сообщение от конечного пользователя.

Это:
- вопрос;
- команда;
- запрос;
- данные пользователя.

Примеры:
```
User:
Как работает Kafka?
```

или:
```
User:
Переведи этот текст на английский.
```

В LangChain эта роль представлена классом:
```
HumanMessage
```

Пример:
```python
from langchain_core.messages import HumanMessage

message = HumanMessage(
    "Что такое Spring Boot?"
)
```

---

### Assistant role (роль ассистента)

**Assistant** — это сообщение, созданное самой моделью.

Оно содержит результат генерации.

Пример:

```
Assistant:
Spring Boot — это фреймворк для создания приложений на Java...
```

В LangChain:

```
AIMessage
```

Например:

```python
response = model.invoke(messages)

print(response)
```

Результат:

```python
AIMessage(
    content="Spring Boot — это..."
)
```

Обычно разработчик не создаёт `AIMessage` вручную.

Он появляется после вызова модели.

---
### Взаимодействие ролей в диалоге

Реальный запрос к модели выглядит примерно так:

```json
[
  {
    role: "system",
    content: "Ты Java эксперт"
  },

  {
    role: "user",
    content: "Что такое JVM?"
  },

  {
    role: "assistant",
    content: "JVM — это виртуальная машина Java..."
  },

  {
    role: "user",
    content: "А как она работает?"
  }
]
```

Модель получает всю историю и генерирует новый ответ:
```
assistant:
JVM выполняет байткод...
```

# Типы сообщений в LangChain

## Зачем нужны типы сообщений

LangChain представляет роли через специальные классы.

**Вместо ручного создания JSON:**

```json
{
  "role": "user",
  "content": "Привет"
}
```

**используются Python-объекты**:
```python
HumanMessage("Привет")
```

Они позволяют удобно создавать историю диалога и работать с цепочками LangChain.

---
## HumanMessage

`HumanMessage` представляет сообщение пользователя.

Соответствует роли:

```
HumanMessage → user
```

Используется для:
- вопросов пользователя;
- команд;
- входных данных.

Пример:
```python
from langchain_core.messages import HumanMessage

message = HumanMessage(
    "Объясни принцип работы Kafka"
)
```

В API это превращается в:
```json
{
  "role": "user",
  "content": "Объясни принцип работы Kafka"
}
```

---
Пример диалога:
```json
messages = [
    HumanMessage(
        "Что такое Docker?"
    )
]

model.invoke(messages)
```

Модель получает запрос пользователя и отвечает.

---
## SystemMessage

`SystemMessage` представляет системную инструкцию.

Соответствует роли:
```
SystemMessage → system
```

Используется для настройки поведения модели.

Пример:
```python
from langchain_core.messages import SystemMessage

message = SystemMessage(
    "Ты отвечаешь как senior Java разработчик"
)
```

Запрос:
```json
messages = [
    SystemMessage(
        "Ты Java эксперт"
    ),
    HumanMessage(
        "Что такое JVM?"
    )
]
```

Модель получит:
```
System:
Ты Java эксперт.

User:
Что такое JVM?
```

Ответ будет сформирован с учетом роли эксперта.

---
## AIMessage - ответ модели, для хранения истории

`AIMessage` представляет ответ модели.

Соответствует роли:
```
AIMessage → assistant
```

Обычно создаётся автоматически.

Пример:
```python
response = model.invoke(
    [
        HumanMessage(
            "Что такое Redis?"
        )
    ]
)
```

Ответ:
```python
AIMessage(
    content="Redis — это..."
)
```

---

`AIMessage` **нужен для хранения истории**.

Например:

Первый запрос:
```
User:
Кто создал Java?

Assistant:
Джеймс Гослинг.
```

В приложение сохраняется:
```json
[
    HumanMessage(
        "Кто создал Java?"
    ),

    AIMessage(
        "Джеймс Гослинг."
    )
]
```

Следующий запрос:
```
User:
А где он работал?
```

Отправляется вместе с предыдущими сообщениями:
```json
[
    HumanMessage("Кто создал Java?"),
    AIMessage("Джеймс Гослинг."),
    HumanMessage("А где он работал?")
]
```

Теперь модель понимает, что "он" — это Джеймс Гослинг.

---
## ChatMessage

`ChatMessage` — универсальный тип сообщения с произвольной ролью.

Соответствует:
```
ChatMessage → любая роль
```

Пример:
```python
from langchain_core.messages import ChatMessage

message = ChatMessage(
    role="developer",
    content="Проверь этот код"
)
```

Получится:
```
Developer:
Проверь этот код
```

Используется редко, потому что стандартных ролей обычно достаточно:
- `SystemMessage`;
- `HumanMessage`;
- `AIMessage`.

---
## Сравнение типов сообщений

|LangChain тип|Роль API|Кто создаёт|Назначение|
|---|---|---|---|
|`SystemMessage`|system|Разработчик|Инструкции модели|
|`HumanMessage`|user|Пользователь/приложение|Запрос пользователя|
|`AIMessage`|assistant|Модель|Ответ модели|
|`ChatMessage`|произвольная|Разработчик|Своя роль|
